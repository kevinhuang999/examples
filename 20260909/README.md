# 示例：按 Excel 模板批量生成检验报告

配套长文：《Excel 模板批量填充保留格式》（CSDN 发布后补链接）
`run.py` 里的核心代码与文章正文**逐字一致**，跑通即等于文章代码跑通。

## 一、怎么跑

本文件跟 `run.py` 并排放在最外层，看完接着跑就行。一条命令，Windows / macOS / Linux 通吃：

```bash
python run.py
```

Windows 上也可以**直接双击 `run.py`**：脚本会自己切到所在目录、缺 openpyxl 就自动装、
跑完停住窗口等你按回车。不想停就加 `--no-pause`。

依赖只有一个 openpyxl。想先手动装：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple openpyxl
```

跑完看 `02_output/`，生成 3 份报告，并自动回读验证 9 项，全绿打印 PASS。
日志写进 `source/run_log.txt`（UTF-8，**每次追加**，不覆盖历史）。每段日志开头记「开始执行」时间与解释器，
结尾记「执行完成」时间、用时和判定。

> 完成行是在结束时**立即**写下的，不等你按回车。所以跑完直接关窗口，日志里照样有完成时间和判定。
> 万一某一条只有开始、没有完成（比如跑到一半强制中断），下一次运行会在日志里补一句「上一条没有留下完成时间」，
> 不会静默缺一段。

## 二、目录结构

外层只放你要碰的四样东西（01 → 02 就是操作顺序），其余全收进 `source/`：

```
20260909/
├── README.md               ← 本文件，先看这个
├── run.py                  ← 再跑这个
├── 01_raw_data/            ← 你的原始数据放这
│   └── results.csv         15 行明细 / 3 个样品，带 BOM，模拟 LIMS 导出
├── 02_output/              ← 跑完的成品在这（脚本自动生成）
└── source/                 ← 模板、日志、维护脚本；日常不用碰
    ├── templates/
    │   └── 检验报告模板.xlsx 仿真实报告：合并单元格、命名区域、60 行明细区、结论公式、签字栏
    ├── run_log.txt         运行日志（脚本自动生成，每次追加）
    ├── build_fixtures.py   重新生成模板和 CSV（改了模板结构后重跑）
    └── requirements.txt    依赖清单（只有 openpyxl）
```

整个目录直接拷给别人就能用：脚本用 `Path(__file__).parent` 定位，没有硬编码路径。

## 三、数据故意造了这些边界

| 样品 | 明细条数 | 测什么 |
| --- | --- | --- |
| S-2026-0001 注射用头孢曲松钠 | 3 项 | 基本情况；检出限 0.050 看数字格式 |
| S-2026-0002 阿托伐他汀钙片 | 11 项 | 条数多的情况；性状/鉴别/重金属为空值，测 `float("")` 崩溃 |
| S-2026-0003 氯化钠注射液 | 1 项 | 条数最少；批号 `0260903` 测前导零 |

## 四、造数据时发现的三个问题（文章已改）

1. **打印区域写死到 `last + 6` 会切掉结论行和签字栏。**
   模板里结论行在第 72 行、签字栏 74-76 行，行号不随明细条数变。
   3 条明细时 `last + 6 = 20`，打印区域变成 A1:G20，结论和签字全没了。
   改成固定 `ws.print_area = f"A1:G{FOOTER_LAST}"`。

2. **`float(it["检验结果"])` 遇到空值直接崩。**
   定性项目没有数值，CSV 里是空的，报 `ValueError: could not convert string to float: ''`。
   改成先判空再转，空写 None。

3. **`ws["命名区域"]` 在 openpyxl 3.1.5 根本不支持。**
   报 `ValueError: 样品编号 is not a valid coordinate or range`，必须用 `cell_by_name()` 解析。

## 五、验证环境

- Python 3.13 + openpyxl 3.1.5，实测 PASS。
- 三个样品 9 项检查全绿：抬头写入、数字格式 0.000、边框、合并区、结论公式、
  结论行在打印区内、明细末行未隐藏、多余行已隐藏、强制重算。
- 实测覆盖四种环境：①已装依赖的解释器 ②全新空虚拟环境（自动装 openpyxl 后跑通）
  ③系统 Python 双击场景 ④整个目录拷到别处、从别的目录跑。
- 三个平台同一条命令。平台相关的代码只有一处：Windows 才在结束时暂停等回车。

## 六、给别人用的注意事项

| 项 | 说明 |
| --- | --- |
| 依赖 | 只需 openpyxl，脚本会自动装 |
| Python 版本 | 3.9 以上（代码用了 `list[dict]` 注解，3.8 会报 TypeError） |
| 路径 | 全相对定位，拷到哪都能跑 |
| 编码 | CSV 是 utf-8-sig，Excel 直接打开中文不乱码 |
| 日志 | `source/run_log.txt` 每次追加，带开始/完成时间和用时，历史不丢 |
| 要改的地方 | 模板里的"XX 检测技术有限公司"换成你自己的抬头；`01_raw_data/results.csv` 换成真实数据 |
| 已知限制 | openpyxl 存盘会丢图表、图片、透视表。报告里要放图的，别用这套 |

## 七、排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `02_output/` 是空的 | 脚本没跑到生成那步 | 看 `source/run_log.txt`，或命令行跑一遍看报错 |
| 自动装 openpyxl 失败 | 无写入权限 / 网络不通 | 手动：`python -m pip install --user -i https://pypi.tuna.tsinghua.edu.cn/simple openpyxl` |
| 控制台中文乱码 | cmd 代码页问题 | 看 `source/run_log.txt` |
| `ValueError: 不是有效坐标` | 模板里的命名区域被删了 | 用 `source/build_fixtures.py` 重新生成模板 |

## 八、拿到 Excel 里要看什么

1. 打开 `02_output/` 里任意一份，看第 12 行起明细的格式是不是跟模板一个样。
2. 第 72 行结论应该有文字（公式重算后的结果），空白说明 `fullCalcOnLoad` 没生效。
3. Ctrl+P 预览，确认打印区域包含结论和签字栏，中间没有大段空白页。
4. 把 3 条明细和 11 条明细的两份对比看，页脚位置应该完全一致。

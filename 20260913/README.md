# 示例：稳定性考察数据按批次×时间点自动汇总成一张表

仪器导出的明细是**一行一个检项**（长表），稳定性考察报告要的是**一行一个检项、一列一个时间点**（宽表），
一个批次一张。手工就是在 Excel 里反复插入透视表、拖字段、改列顺序，五个批次就得拖五遍。

这个示例用 pandas 的 `pivot_table` 一步转过来：5 个批次的汇总表写进同一个 xlsx，一个批次一个页签，
检项按药典体例排行，超标的格子自动刷红。

## 原始数据长什么样

一个检项一行，同一个批次的时间点重复出现——这是**长表**，人看着啰嗦，但机器最好处理：

| 批号 | 时间点 | 检项 | 标准规定 | 检验结果 | 单位 |
| --- | --- | --- | --- | --- | --- |
| 240905 | 0 天 | 性状 | 白色或类白色粉末 | 白色粉末 | |
| 240905 | 0 天 | 鉴别 | 应与对照品一致 | 符合 | |
| 240905 | 0 天 | 有关物质 | ≤ 0.5% | 0.12 | % |
| 240905 | 1 个月 | 性状 | 白色或类白色粉末 | 白色粉末 | |

转出来的**宽表**才是要交的报告：

| 检项 | 标准规定 | 单位 | 0 天 | 1 个月 | 3 个月 | 6 个月 |
| --- | --- | --- | --- | --- | --- | --- |
| 性状 | 白色或类白色粉末 | | 白色粉末 | 白色粉末 | 白色粉末 | 白色粉末 |
| 鉴别 | 应与对照品一致 | | 符合 | 符合 | 符合 | 符合 |
| 有关物质 | ≤ 0.5% | % | 0.12 | 0.12 | 0.12 | **0.63** |

## 数据故意造了哪些边界

| 边界 | 在哪 | 想验证什么 |
| --- | --- | --- |
| 批号 `00903` 带前导零 | 第 3 个批次 | 全程按文本读，前导零不能丢；`00903` 被猜成数字就变成 `903`，成了另一个批次 |
| 时间点文字不按字典序 | `0 天 / 1 个月 / 3 个月 / 6 个月` | 直接排会成 `0 天 / 1 个月 / 3 个月 / 6 个月` 看似对的，但 `10 个月`、`12 个月` 一进来就乱 |
| 一个批次缺一个时间点 | `00903` 只有 3 个时间点（6 个月还没到） | 列数对不齐是常态，不能凭空补一列空的 |
| 结果里有空值 | `240906` 的「干燥失重 / 6 个月」、`241115` 的「重金属 / 3 个月」 | 空格子要留白，不能变成 `NaN` 三个字母 |
| 结果是文字不是数字 | 「性状」「鉴别」「溶解度」三行 | 数值汇总不能拿来套文字行 |
| 区间标准 | 含量测定 `98.0%~102.0%` | 只写上限会漏判低于下限的情况 |
| 一批超标 | `241115` 的「有关物质 / 6 个月」= 0.63（限 ≤0.5%） | 越界格子要能自动挑出来标红 |
| 检项 1 条 / 12 条 | `241012` 只有 1 项、`241115` 有 12 项 | 极多极少都不能报错，12 项那张表很宽 |
| 表尾三行垃圾 | CSV 末尾空行 + 「合计」+ 说明行 | 不能被当成数据，多出一个「合计」批次 |

## 实测发现的问题与改法

1. **`pivot_table` 出来的行序是拼音序，不是报告体例。** 第一次跑出来 `pH 值` 排在第一行、
   `含量测定` 掉到最后——因为 pivot 按检项名排序。稳定性报告的检项顺序是固定的（性状、鉴别、检查项、含量），
   得自己拿一张 `ITEM_ORDER` 表把行 order 拉回来。这是最容易被忽略的一处。
2. **空字符串写进 Excel，读回来还是 `NaN`。** `fillna("")` 只管写入那一刻；空单元格在 Excel 层就是空的，
   pandas 读回默认还给 `NaN`。要读到空字符串，得 `read_excel(..., keep_default_na=False)`。
   报告里出现 `NaN` 三个字母，客户一眼就看出来是脚本糊的。
3. **区间标准不能只判上限。** 含量测定是 `98.0%~102.0%`，一开始只用一张「上限表」判定，
   结果**下限没人管**——103% 会被放过去，但 97% 同样不合格却要靠人看。
   改成 `(下限, 上限)` 元组，`None` 表示那一头不管，上限项和区间项用同一套逻辑。
4. **`aggfunc="sum"` 会把重复取样加两遍。** 同一个批次同一时间点同一个检项，正常只有一条记录；
   万一仪器导出了重复行，`sum` 会默默相加（`0.12 + 0.12 = 0.24`），结果错了还不报错。
   用 `first`（或用 `aggfunc="max"`，看业务口径），并在读数据时按业务键去重。
5. **批号前导零。** `read_csv` / `DataFrame` 不指定 `dtype=str` 时会猜类型，`00903` → `903`。
   必须全程按文本读，事后 `astype(str)` 补不回已经丢掉的零。
6. **时间点的顺序不能靠排序。** `0 天 / 1 个月 / 3 个月 / 6 个月` 看着按字典序也还行，
   但一加 `10 个月`、`12 个月`，字典序会把 `10 个月` 排到 `1 个月` 前面。
   时间点的先后是考察方案定的，单独落一份顺序文件，按它 `reindex` 列。
7. **CSV 用 Excel 打开全是乱码。** 纯 UTF-8（不带 BOM）的文件，Excel 双击会按 ANSI 解码。
   改法：写 CSV 时用 `utf-8-sig`（带 BOM），`run.py` 读的时候也用 `utf-8-sig`，带不带 BOM 都能读。

## 验证环境与已知限制

- 实测环境：Windows + Python 3.13 + pandas 3.0.5 + openpyxl 3.1.5；115 行明细 → 5 个批次页签，11 项回读校验全绿 PASS。
- 判定界限（`STD_LIMIT`）是示例写死的，真实场景里标准规定会变（不同品种、不同版本药典）。
  它只用来**标出值得看的格子**，不替代人工判定；上线前按自己的品种表核对一遍。
- 一个批次一个页签，批次数很多时（几百个）页签会挤满，那种场景更适合按批次拆成独立的 xlsx。
- `source/run_log.txt` 里带着运行主机名和 IP，是给排查用的；对外发这份示例前把这几行删掉。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 批号里的 `00903` 变成 `903` | 按数字读了 | 读 CSV / DataFrame 时 `dtype=str`，全程按文本 |
| 汇总表里多出一个「合计」页签 | CSV 表尾的合计行没被过滤 | 判空要看「批号 + 时间点 + 检项」三个字段 |
| 检项行序不是想要的顺序 | pivot 按检项名排序 | 用 `ITEM_ORDER` 表 `reindex` 行 |
| 时间点列序乱（`10 个月` 跑到前面） | 按字典序排了 | 从考察方案文件读顺序，`reindex(columns=...)` |
| 格子里显示 `NaN` | 空单元格读回默认是 NaN | 读回校验时 `keep_default_na=False`；写入前 `fillna("")` |
| 数字被加了两次 | `aggfunc="sum"` 遇上重复记录 | 换 `first`，或读数据时按业务键去重 |
| 低于下限的不合格没标出来 | 只判了上限 | 界限写成 `(下限, 上限)` 元组 |
| 用 Excel 打开 CSV 全是乱码 | 文件是纯 UTF-8 不带 BOM | 跑 `python source/build_fixtures.py` 重新生成（已带 BOM） |
| 跑完窗口一闪就没了 | 双击运行的窗口在结束后关闭 | 直接跑 `python run.py`，或看 `source/run_log.txt` |

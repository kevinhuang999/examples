# 示例：一个样品一份 Word 检验报告（模板占位符 + 明细表动态加行）

配套文章：《Word 邮件合并批量生成检验报告，多条检项却只出来一行》

一份报告里既有样品级的信息（样品名称、批号、送检部门），又有一个样品若干行的检项明细。
邮件合并处理前者没问题，处理后者就得靠域代码硬撑；这里用 `python-docx` 直接干：
把模板里的占位符换成值，再把明细表的样例行按检项数复制成 N 行，一个样品存一个 `.docx`。


## 怎么跑

```bash
python run.py                # 双击 run.py 也行
python run.py --no-pause     # 不暂停等回车（CI / 脚本里用）
```

缺 `python-docx` 会自动用清华源装；装不上会打印手动命令。
路径全部相对定位（`Path(__file__).resolve().parent`），整个目录拷到别的电脑照样跑。

手动装依赖：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r source/requirements.txt
```

重造模板与数据（改了数据想再跑一遍时用）：

```bash
python source/build_fixtures.py
```

**注意**：`build_fixtures.py` 会覆盖 `01_raw_data/` 里那两份 CSV 和 `source/templates/检验报告_模板.docx`。

## 数据故意造的边界

正常数据跑通不代表对，所以每一处边界都是故意留的：

| 边界 | 造在哪 | 不处理会怎样 |
| --- | --- | --- |
| 样品名带斜杠 | `阿莫西林/克拉维酸钾片` | 直接拿它命名文件会建出子目录，或者直接报错 |
| 样品编号带前导零 | `00903` | 当数字读一遍就变成 `903`，文件名叫错 |
| 检项极多 | `S2026090004`，12 项 | 明细表行数不够，后面 11 项没地方放 |
| 检项极少 | `00903`，1 项 | 多复制出来的空行会留在报告上 |
| 一个检项都没有 | `S2026090006`（结果还没录） | 报告里留一行 `{{检项}}` 没换掉的空占位符 |
| 结果为文字 | `符合` / `不符合` 和数字混在同一列 | 按数字读会抛异常，或者被转成 `NaN` |
| 结果带符号 | 有空结果格子 | 写成 `0` 或 `None`，客户一眼看出是脚本糊的 |
| 占位符被拆成多个 run | 模板里 `{{样品编号}}`、`{{样品名称}}` | 逐个 run 做 replace 一处都换不到，报告上留一堆 `{{ }}` |
| CSV 尾巴 | 空行 + `合计` 行 + `说明` 行 | 被当成数据，凭空多出样品 |

## 造数据/写代码时实测发现的问题

1. **模板里 `{{样品编号}}` 被 Word 拆成了三个 run**。这是 Word 存盘和拼写检查的常规操作，
   于是「遍历 run 逐个 replace」这套写法一处都换不到。改成先把整段文本拼起来、再写回第一个 run。
   本示例的模板是故意这么存的，不修就跑不出正确报告。
2. **`cell.text = "值"` 会把模板排好的字号一起清掉**。它内部是把单元格内容全部清空再重建一个段落，
   所以明细行的字号会退回表格默认值。写进第一个 run（`cell.paragraphs[0].runs[0].text = 值`）才保得住。
3. **`python-docx` 没有「插入行」的 API**。表格要在中间长行，只能 `copy.deepcopy(那一行的._tr)`
   再挂回表格，复制出来的行自带模板行的字号与边框，比自己画一行省事。
4. **样品名里的 `/` 会让文件建不出来**。实测 `检验报告_S2026090005_阿莫西林/克拉维酸钾片.docx`
   在 Windows 上会被当成两级目录；换成横线才落得下去。
5. **一个检项都没有的时候，模板那行必须删掉**。不删就留一行没换掉的 `{{检项}}` 在报告上——
   这种报告发出去，等于自己告诉对方这是脚本生成的。
6. **结论不能让脚本瞎写**。有 `不符合` 就是不符合规定；有结果还没出的，写「待结果出齐后判定」；
   全符合才写符合规定。本示例里 `S2026090001` 有关物质 0.68 超标，结论自动变「不符合规定」。

## 验证环境与已知限制

- 实测环境：Windows + Python 3.13，`python-docx` 1.2.0。
- 回读校验 12 项全绿（`PASS`），日志在 `source/run_log.txt`。
- 模板里的版式（页眉、页脚、打印区域、签字栏位置）本示例没涉及，真实报告要保留这些，
  做法一样：版式在模板里排好，脚本只负责换字和长行。
- 转 PDF 打印用 Word 另存或 `docx2pdf`，不在本示例范围内。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报告上留着一堆 `{{字段}}` | 该字段不在 `mapping` 里，或占位符被拆得不在同一个段落 | 占位符拆在多个 run 没关系（`fill_paragraph` 已处理），但**不能跨段落**；对着模板核字段名 |
| 明细表只有一行 | 明细 CSV 里没有这个样品编号的行 | 看 `01_raw_data/检项明细_仪器导出.csv` 第一列是不是样品编号 |
| 明细行字号变了 | 直接用了 `cell.text = ...` | 改回 `write_cell()`，文本写进第一个 run |
| 报 `FileNotFoundError` 或生成出一层文件夹 | 样品名里有 `/` `\` `:` 之类字符 | 走 `safe_name()` 再拼文件名 |
| 结论写成了「待结果出齐后判定」 | 该样品有格子是空的 | 补数据；这是有意设计，空结果不该被当成合格 |
| 中文变乱码 | CSV 被按 ANSI 打开 | 文件是 `utf-8-sig`（带 BOM），用 Excel 双击或 `encoding="utf-8-sig"` 读 |

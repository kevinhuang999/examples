# 示例：中心实验室样本接收登记表（扫码记录 + 温控记录 → 一管一管判异常）

配套文章：《中心实验室样本接收登记，一批几百管靠手工核到半夜》

样本一到就是几十上百管：扫码枪扫出来的接收明细是一个文件，温控记录仪导出的运输温度是另一个文件，
两边要按运单号对起来，再一管一管看温度超没超、送得超没超时、外观有没有问题、访视点在不在方案里。
这里用 `openpyxl` 直接干：拼成一份登记总表，异常的整行刷色，再单独拎成一页异常清单交给中心确认。

## 目录结构

```
20260915/
├── README.md                ← 你正在看的这个
├── run.py                   ← 入口，跑主线（生成样本接收登记表）
├── 01_raw_data/             ← 输入，你要碰的就是这两个 CSV
│   ├── 样本接收明细_扫码枪导出.csv   一管一行：编号、中心、访视点、类型、采样/接收时间、外观备注
│   └── 温控记录_记录仪导出.csv       一趟车一行：运单号、最高温、最低温、干冰余量
├── 02_output/               ← 跑完生成，样本接收登记表.xlsx（不入库）
└── source/                  ← 其余都在这里，不用动
    ├── build_fixtures.py     重造两份 CSV（上半造温控记录，下半造样本明细）
    ├── requirements.txt
    └── run_log.txt           运行日志（脚本追加写入，不入库）
```

`source/templates/` 是空的——本示例不套模板，登记表是脚本从头生成的。

## 怎么跑

```bash
python run.py                # 双击 run.py 也行
python run.py --no-pause     # 不暂停等回车（CI / 脚本里用）
```

缺 `openpyxl` 会自动用清华源装；装不上会打印手动命令。
路径全部相对定位（`Path(__file__).resolve().parent`），整个目录拷到别的电脑照样跑。

手动装依赖：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r source/requirements.txt
```

重造数据（想再跑一遍时用）：

```bash
python source/build_fixtures.py
```

**注意**：`build_fixtures.py` 会覆盖 `01_raw_data/` 里那两份 CSV。

## 输出长什么样

一个 `02_output/样本接收登记表.xlsx`，三个页签：

| 页签 | 内容 | 给谁看 |
| --- | --- | --- |
| 登记总表 | 一管一行，13 列，异常行整行刷色（要确认的淡红、记偏差的淡黄） | 接收岗自己核 |
| 异常样本清单 | 只留非合格的 25 管，带上异常说明 | 直接拿去发邮件找中心确认 |
| 中心汇总 | 每个中心的接收管数、合格数、合格率 | 项目组报数 |

## 数据故意造的边界

正常数据跑通不代表对，所以每一处边界都是故意留的：

| 边界 | 造在哪 | 不处理会怎样 |
| --- | --- | --- |
| 冷藏超上限 | 运单 `T260915002`，最高 11.8℃ | 该趟车 6 管全漏，报告上全是"合格" |
| 冷藏低于下限 | 运单 `T260915003`，最低 0.4℃ | 只写 `if 最高温 > 8` 会漏掉疑似冻结那批 |
| 干冰趟正常 | 运单 `T260915004`，-72.5~-68.0℃ | 把 -68 当"低于 2℃"判异常，全场误报 |
| 干冰不足 | 运单 `T260915005`，最高 -52℃ | 干冰温度不压到 -60 以下，样本已经不能用了 |
| 送达超时 | `01001004-EDTA01`，采样 47 小时前 | 时限按样本类型卡，全血 24h、血清 48h、干冰 72h |
| 采样时间空着 | `01002010-SER01` | 判不了时限时默认合格等于放水，得标出来 |
| 外观异常 | `溶血` / `量不足` | 记偏差但不影响接收，跟温度问题是两档处理 |
| 访视点不在方案 | `第3周期D1` | 方案只到第 2 周期，多半是中心填错 |
| 样本类型不认识 | `脑脊液` | 不在接收规则里的类型不能猜，得标出来要规则 |
| 没有温控记录 | 运单 `T260915099` 在温控文件里查不到 | 查不到≠没超温，不能当合格 |
| 编号带前导零 | 中心编号 `01001`、受试者编号 `01001001` | 按数字读会变成 `1001`，跟中心对不上 |
| 表尾脏行 | 两份 CSV 尾部的空行 + `合计` 行 + `说明` 行 | 被当成数据，凭空多出一管叫"合计"的样本 |

## 造数据/写代码时实测发现的问题

1. **温控记录是"一趟车一行"，样本明细是"一管一行"，两边粒度不一样**。这不是数据脏，是两套记录方式：
   记录仪只记运输箱，箱子里塞了几十管。所以必须先按运单号把温度挂到每一管上再去判，
   否则要么漏判一整趟车，要么一管一管重复读文件。
2. **温度阈值是有区间的，不是只卡上限**。冷藏要求 2~8℃，只写 `最高温 > 8` 判超温，
   会漏掉 `最低温 < 2`（疑似冻结，同样不能用）；干冰又是另一种写法——只要最高温低于 -60℃，
   最低温掉到 -80℃ 反而更好。所以规则表里的下限写 `None` 表示"那一头不管"。
3. **温度查不到的时候不能当 0℃**。记录仪偶尔吐空值、或者运单号在面单上打错，
   这时候 `temp` 是空字典。当成 0℃ 会让 2~8℃ 的样本判成"低于下限"，
   当成合格又会放走真正超温的批次。应当单独标"无温控记录"，按待确认处理。
4. **判定不是"合格/拒收"两态**。接收 SOP 里分三级：记录备案、隔离待评估、拒收启动偏差。
   本示例压成三档——`待中心确认`（温度、时限出问题）、`有偏差接收`（外观、信息对不上）、
   `合格接收`。混成一档会让异常清单没法用：外观有问题的管照样能检测，不能跟超温的摆一起。
5. **表尾的合计行会把条数吞进数据里**。扫码枪和记录仪导出的文件尾部都是空行 + 合计 + 说明，
   合计行的文本落在第一列（运单号），样本编号是空的，靠"样本编号非空"才丢得掉。
6. **整行刷色是给人看的，不是给机器看的**。接收岗一天要过几百管，不会一行一行读结论列；
   把非合格行整行刷色，扫一眼就知道哪几管要拎出来，白底的直接入库。

## 验证环境与已知限制

- 实测环境：Windows + Python 3.13，`openpyxl` 3.1.5。
- 回读校验 15 项全绿（`PASS`），日志在 `source/run_log.txt`。
- 本示例只做到"生成登记表 + 挑出异常"，**不自动发邮件、不改任何系统数据**：
  异常清单是给人拿去发邮件、或者在系统里改状态的。
- 存储位置、冻融次数、后续分装这些环节不在本示例范围内。
- 把整包发给别人时，`source/run_log.txt` 里有本机主机名与 IP，按需删掉或只发代码。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 全部判成"无温控记录" | 温控 CSV 里的运单号跟明细对不上（空格、大小写、面单号写错） | 两边都 `.strip()` 过一遍；对不上的运单号本来也该报出来 |
| 干冰批次全判"低于下限" | 给干冰类型填了 2~8℃ 的下限 | 规则表里干冰那行的下限写 `None` |
| 某管一直判"送达超时" | 采样时间写成了接收时间，或者时区/格式不一致 | 统一成 `YYYY-MM-DD HH:MM`；空值会被判"判不了时限" |
| 异常清单里出现了正常样本 | 判定的阈值与实际 SOP 不一致 | 改 `SAMPLE_RULES` 和 `PLAN_VISITS`，别改判定逻辑 |
| 打开的 xlsx 中文变乱码 | 读的是 CSV 用的编码 | CSV 是 `utf-8-sig`（带 BOM），用 `encoding="utf-8-sig"` 读 |
| 报 `PermissionError` | xlsx 正在 Excel 里打开着 | 关掉 Excel 再跑 |

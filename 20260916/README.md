# 示例：把方案规格变成 Kit 配置单（几套、领多少料、贴什么标签）

配套文章：《一份方案改一次，几百套采血 Kit 的配置单就全得重抄》

一份方案定下来，中心实验室就得按它给每个中心配采血 Kit：哪个访视点采哪几种管、各几支。
方案规格文件给的是**每例用量**，中心入组计划给的是**各中心几例**，仓库台账给的是**各批次有几支**——
这三份东西要乘一遍、对一遍，才能变成一张「这家中心这几个访视点各配几套、每样管领多少支、每支贴什么标签」的配置单。

这里用 `openpyxl` 直接干：算套数、按 FEFO 排料、按套展开标签，料不够和名字对不上的一并列成待办页。

## 目录结构

```
20260916/
├── README.md                ← 你正在看的这个
├── run.py                   ← 入口，跑主线（生成 Kit 配置清单）
├── 01_raw_data/             ← 输入，你要碰的就是这三个 CSV
│   ├── 研究规格_方案导出.csv          一行一种管：模板、访视点、管型、每例管数、采血量、处理要求
│   ├── 中心入组计划_项目组导出.csv     一个中心一行：用哪个模板、计划几例、启动日期
│   └── 物料批次_仓库导出.csv          一个管型挂好几个批次：批次号、效期、库存支数
├── 02_output/               ← 跑完生成，Kit配置清单.xlsx（不入库）
└── source/                  ← 其余都在这里，不用动
    ├── build_fixtures.py     重造三份 CSV（上半造方案与计划，下半造物料批次）
    ├── requirements.txt
    └── run_log.txt           运行日志（脚本追加写入，不入库）
```

`source/templates/` 是空的——本示例不套模板，配置单是脚本从头生成的。

## 怎么跑

```bash
python run.py                # 双击 run.py 也行
python run.py --no-pause     # 不暂停等回车（CI / 脚本里用）
```

缺 `openpyxl` 会自动用清华源装；装不上会打印手动命令。
路径全部相对定位（`Path(__file__).resolve().parent`），整个目录拷到别的电脑照样跑。

手动装依赖：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r source/requirements.txt
```

重造数据（想再跑一遍时用）：

```bash
python source/build_fixtures.py
```

**注意**：`build_fixtures.py` 会覆盖 `01_raw_data/` 里那三份 CSV。

## 输出长什么样

一个 `02_output/Kit配置清单.xlsx`，四个页签：

| 页签 | 内容 | 给谁看 |
| --- | --- | --- |
| Kit 组装清单 | 12 行 = 4 个有效中心 × 3 个访视点，写清每家几套、每套几支、实际组进去几支 | 组装岗照着组 |
| Kit 领料明细 | 32 行，一管型可能拆成两三个批次行，带批次号与效期 | 库房照单发料 |
| 标签打印清单 | 254 张标签，一个「中心-访视-套号-管位」一行，导去打标机 | 打标岗 |
| 异常与提醒 | 8 条待办，整行刷色 | 项目组：要拍板、要催料、要找方案的事都在这页 |

实测一条：**标签数 = 领用支数合计 = 254**。每支管子一张标签，这两个数对不上就是哪里漏了。

## 数据故意造的边界

正常数据跑通不代表对，所以每一处边界都是故意留的：

| 边界 | 造在哪 | 不处理会怎样 |
| --- | --- | --- |
| 方案修订留下的重复行 | 「标准」模板的基线促凝管出现两行：2 支、1 支 | 用字典直接覆盖会静默丢一行；取错了整套 Kit 少一半促凝管 |
| 方案里有、仓库没这个规格 | 血沉管，物料表里没有对应条目 | 猜一个近似的顶上，采出来的结果不能用 |
| 效期盖不到采样窗口 | EDTA 批次 `B2302C`（2026-11-30）、促凝管 `B2301D`（2026-12-31） | 只判"今天没过期"就发出去，料到了中心已经过期 |
| 同一管型跨两个批次 | 促凝管 FEFO 先出 `B2509B` 60 支，再出 `B2601A` 41 支 | 不拆批次要么少发、要么全从新批次发，老料烂在库里 |
| 库存不够 | 冻存管外旋只有 30 支，两个中心共要 34 支 | 扣了一半料、Kit 又组不起来，料还被占着 |
| 规格相近的干扰料 | 冻存管 2mL **内旋** 300 支、蓝帽 **3.8%** 凝血管 150 支 | 模糊匹配会把它们并成一种，凝血数据整批作废 |
| 中心还没启动 | `01003` 广州中心，计划例数 0 | 当成 0 支跳过，中心开组时发现一包 Kit 都没有 |
| 访视模板对不上 | `01006` 曼谷中心填的是「加强」，方案里没这个模板 | 悄悄跳过，这个中心从此没人管 |
| 编号带前导零 | 中心编号 `01001` | 按数字读会变成 `1001`，标签上印错就取不到货 |
| 表尾脏行 | 三份 CSV 尾部的空行 + `合计` 行 + `说明` 行 | 被当成数据，凭空多出一个叫"合计"的中心 |

## 造数据/写代码时实测发现的问题

1. **套数不能乘访视点数**。套数 = 计划例数——一个受试者来一个访视点领一套 Kit。
   把例数乘到套数上（12 例 × 3 个访视点 = 36 套）看着"全面"，实际是给同一个受试者多备了三倍。
   要乘的是**领用支数**：套数 × 每例管数。这两个数混了，标签会整包多印。
2. **发料是 FEFO，不是随便挑一批**。先出效期最近的，同效期按批次号。
   一个中心的需求跨两个批次时，领料明细里就得按批次拆行，否则库房照单发不出来。
3. **效期要跟"最晚可用日"比，不是跟今天比**。料验收入库、组装、发运、中心放着备用、受试者到访采样，
   中间隔好几个月。本示例用「组装日 + 120 天（中心放置 3 个月 + 采样窗口 1 个月）」当底线，
   只跟今天比的脚本会把 2026-11 到期的批次照发不误。
4. **排料"先算总账再动料"**。一支一支往下扣，扣到一半发现不够，这时候料已经被占了、
   Kit 也组不起来，后面的中心还领不到。所以 `allocate()` 先判总量，不够就整项退回、一支不扣。
5. **管型名称必须显式映射**。方案上写的是检测用途（「促凝管」），仓库里按规格录料（「黄帽 促凝 5mL」），
   两套叫法得人工对一遍。看着"差不多"就自动匹配，会在 3.2% / 3.8% 凝血管、内旋 / 外旋冻存管上翻车。
6. **标签按套展开，领料按管型合并**。领料是给库房的（同一种管一起发），标签是给现场的
   （一套一个受试者，包内管子连号）。同一份需求两种展开方式，少了一种就有一边对不上。
7. **脚本不替人拍板**。重复行取哪条、缺料是先发还是等等，都是业务决定。脚本负责把冲突和缺口
   摆到待办页上，让人去核方案、催料。

## 验证环境与已知限制

- 实测环境：Windows + Python 3.13，`openpyxl` 3.1.5。
- 回读校验 18 项全绿（`PASS`），日志在 `source/run_log.txt`。
- 实测口径：17 行方案规格 / 6 个中心 / 10 个批次 → 84 套 Kit、254 支料、254 张标签、32 个批次行、8 条待办。
- 本示例只做到"算出来 + 排料 + 出标签清单"，**不连仓库系统、不改任何系统数据、不直接驱动打标机**：
  配置单是给人去下任务、照单发料的。
- Kit 的实物组装顺序、装箱、冷链包装、发运这些环节不在本示例范围内。
- 把整包发给别人时，`source/run_log.txt` 里有本机主机名与 IP，按需删掉或只发代码。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 所有中心都报"访视模板对不上" | 方案规格里的模板名跟入组计划里写的不是同一个词 | 两边名字对齐；对不上的本来也该报出来 |
| 某管型一支都没排 | 方案上的管型名没写进 `TUBE_ALIAS`，或者仓库换了规格名 | 补映射表，别改成模糊匹配 |
| 明明有库存却报"缺料" | 那批料的效期盖不到「组装日 + 120 天」 | 确认货架期常量；或换新批次，或走临时放行流程 |
| 标签数量对不上领料支数 | 有管型被跳过（没映射 / 缺料），标签只按能组的量出 | 看「异常与提醒」页，料齐了重跑 |
| 组装清单的「实际每套管数」小于「计划」 | 该访视点有管型没排上 | 对照"说明"列，逐项补齐 |
| 报 `PermissionError` | xlsx 正在 Excel 里打开着 | 关掉 Excel 再跑 |
| 打开的 CSV 中文变乱码 | 读的是 CSV 用的编码 | CSV 是 `utf-8-sig`（带 BOM），用 `encoding="utf-8-sig"` 读 |

# 示例：多中心检验报告按中心批量分发（改名 + 打包 + 台账）

一批出好的报告，要按中心拆开、按各中心的命名规矩改名、复制成能直接发出去的目录，
还要算得出每一份的 TAT（样本接收日 → 报告日期）、并把编号异常、原件缺失、改名撞名的挑出来。

这个示例把三份东西拼成一份**分发清单**：

```
报告索引（一行一份报告）
+ 中心分发规则（一行一个中心：命名模板、分包方式、接收人、TAT 约定）
+ 报告原件目录（磁盘上实际躺着哪些文件）
→ 02_output/分发包/<中心>/ 里是按本中心规矩改好名的报告
→ 02_output/分发清单.xlsx 三个页签：分发清单 / 报告明细 / 异常与提醒
```

脚本**只备包、只列问题，不代替人发邮件**：分发清单最后一个状态列固定是「待分发」。

**你要碰的只有三处**：`01_raw_data/` 里的三样输入、`run.py` 顶部的路径常量、跑完看 `02_output/`。

## 怎么跑

```bash
python run.py
```

Windows 上也可以直接双击 `run.py`（跑完会停住等回车，不会一闪而过）。
不想暂停就用 `python run.py --no-pause`。

脚本会自己切到所在目录、缺 `openpyxl` 时自动用清华源装、跑完自动回读校验并打印 `PASS/FAIL`。

## 数据是怎么来的

三份输入分别对应三个来源，全是从系统里**导出**出来的，不是在这个脚本里手敲的：

| 文件 | 来源 | 一行是什么 |
| --- | --- | --- |
| `报告索引_系统导出.csv` | 报告系统的导出 | 一份报告（中心、受试者、访视点、样本接收日、报告日期、文件名） |
| `中心分发规则_项目组.csv` | 项目组维护 | 一个中心（命名模板、分包方式、接收人、接收方式、TAT 约定、编号位数） |
| `报告原件/` | 报告系统落盘 | 一个文件就是一份报告 |

**报告原件在真实场景里是 PDF**，本示例用同名 `.txt` 占位 —— 脚本只按文件名处理、从不读内容，
把后缀换成 `.pdf` 一样跑。

## 数据故意造了哪些边界

正常数据跑通不代表对。这 24 份报告里塞了 8 类边界，每一类都对应正文里讲的一个坑：

| # | 边界 | 在哪儿 | 期望行为 |
| --- | --- | --- | --- |
| 1 | 受试者编号带前导零 | `01001` | CSV 按文本读，前导零保得住 |
| 2 | 前导零被吃掉（只剩 4 位） | `RPT-0006` 的 `1004` | 报「编号位数不对」，挂起 |
| 3 | 补号带斜杠 | `RPT-0011` 的 `0204/2` | 改文件名时斜杠换短横线，正常分发 |
| 4 | 同一受试者同一访视点重出报告 | `RPT-0003` / `RPT-0007` | 改名后撞名，两份都挂起，不覆盖 |
| 5 | 报告日期为空 | `RPT-0021` | 报「日期不齐」，挂起（不能当 0 天） |
| 6 | 报告日期早于样本接收日 | `RPT-0013` | 报「日期先后反了」，挂起 |
| 7 | TAT 超时 | `RPT-0004` / `RPT-0010` / `RPT-0018` | 状态仍是「待分发」，但超时列标「是」并列进异常页 |
| 8 | 原件缺一份、目录多一份 | 少 `RPT-0020.txt`、多 `RPT-0099.txt` | 前者报「原件缺失」，后者报「目录里多出来的文件」 |

另外还有两条规则层面的边界：`S05 武汉中心` 的命名模板漏了 `{subj}`（整批会拼成同一个名字，这个中心整批挂起）、
`S06 西安中心` 在规则表里根本没有（它的那份报告没人认领，列进异常页但不进明细）。

## 实测发现了什么问题、怎么改的

1. **TAT 用「报告日期 - 样本接收日」，只有一边为空时不能当 0 天算。**
   0 天看着像当天就出了报告，实际是数据不齐。现在一边为空就挂起。
2. **日期算出来是负数，比超时更该拦。** `RPT-0013` 报告日期比接收日早 2 天 —— 这是系统里日期录错了，
   不是「TAT 很优秀」。单列一类异常，别混进超时里。
3. **编号位数只校短，不校长。**
   早先写的是 `len(编号) != 规则位数`，结果把补号 `0204/2`（6 位）也拦下来了。
   前导零丢掉只会让编号**变短**，补号本来就比常规编号长，所以判据是 `len < 规则位数`。
   这个坑是造数据时踩出来的：正常数据里全是标准 5 位，校不到。
4. **重名不能覆盖，而且不能只挂后面那一份。**
   同一受试者同一访视点重出的报告，算出来是同一个文件名。哪个是最终版，脚本没有依据判断，
   所以两份都挂起交给人核 —— 只挂后一份的话，前一份会被当成正常报告发出去。
5. **分发包重跑要先清空。**
   第一版是 `mkdir(exist_ok=True)` 往下复制，上一批的旧文件会留在目录里混着一起发出去。
   现在每次先 `rmtree` 再重建。
6. **挂起的报告一份都不许进包。**
   包里的每一份都得是能直接发出去的；挂着的混进去，等于把没核过的东西发出去了。

## 验证环境与已知限制

- 验证环境：Python 3.13 + openpyxl 3.1.x，Windows；Linux / macOS 同样跑通（路径全部相对定位）。
- 回读校验 11 项，覆盖三个页签的行数、分发包的文件数、子目录层级、各类型异常条数。
- **不做的事**：不合并 PDF、不发邮件、不点门户上传。真要按受试者合包成一个 PDF，
  得再调 PDF 库；本示例只按受试者分目录归档，这一点在正文里也写了。
- 报告原件是占位文件，内容不是真实报告格式。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 提示缺 `openpyxl` 并自动安装失败 | 机器没网或没权限 | 手动 `python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple openpyxl` |
| 分发包是空的 | 报告全被判挂起 | 看「异常与提醒」页签，多半是编号位数不对或原件不在 `报告原件/` 里 |
| 某个中心一个文件都没有 | 该中心命名模板或规则有问题 | 检查规则表里这个中心的命名模板是否带 `{subj}` |
| 改名后的文件和预期不一样 | 命名模板写法不同 | 模板认 `{site}` `{subj}` `{visit}` `{date}` 四个占位符 |
| 报告文件名里出现下划线 | 原编号里有 `: * ? " < > |` 这类字符 | 属于正常处理，非法字符统一换掉 |
| `02_output/` 里的旧文件还在 | 上一次跑完没删 | 重跑会自动先清空分发包目录 |

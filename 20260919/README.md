# 示例：按访视窗与检项清单，把检验结果拼成一份份访视时点报告

临床试验的访视时点报告，一份份手工拼很费时间，更麻烦的是**超窗和漏项没人盯**：
受试者提前一天来了算不算超窗？某个访视点该做的检查少做了两类，谁发现？

这个示例把方案侧的**访视计划**和**访视点检项清单**，跟仪器导出的**检验结果**对起来，
每个到过访的时点自动出一份报告，另外给一张台账，把超窗、缺项、没出结果的全挑出来。

## 目录结构

```
20260919/
├── run.py                        ← 入口，跑主线（就改这里的路径与字段，别的不动）
├── README.md                     ← 你正在看的这份
├── 01_raw_data/                  ← 原始数据（01 → 02 就是操作顺序）
│   ├── 访视计划.csv              一行一个 受试者 x 访视点：计划日期、窗前、窗后
│   └── 检验结果_仪器导出.csv      一行一个 受试者 x 访视点 x 检项
└── 02_output/                    ← 脚本生成的结果（重跑会先清空）
    ├── 访视时点报告/             一份报告一个文件：S01_00101_SC.xlsx
    └── 访视执行台账.xlsx         台账页签 + 游离记录页签
└── source/
    ├── templates/
    │   └── 访视点检项清单.csv     方案规定：每个访视点该做哪几项
    ├── build_fixtures.py         重造上面那三张表
    ├── requirements.txt
    └── run_log.txt               运行日志（脚本自动生成，追加不覆盖）
```

**你要碰的只有两样**：`01_raw_data/` 里两张表（换成你自己的导出），
和 `run.py` 顶部的路径与字段常量区（列名不一样时改这里）。

## 怎么跑

```bash
python run.py
python run.py --no-pause    # 不暂停，脚本里调用时用
```

Windows 上直接双击 `run.py` 也行，跑完会停在窗口里等回车。
缺 `openpyxl` 会自动用清华源装；装不上会提示手动命令。

手动装依赖：

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple openpyxl
```

重造输入数据（会把 `01_raw_data/` 和 `source/templates/` 覆盖）：

```bash
python source/build_fixtures.py
```

## 数据是怎么来的

`build_fixtures.py` 上下两半分工不同：

- **上半段**建方案侧的两张表：访视点检项清单（22 行，6 个访视点）和访视计划（20 行，7 个受试者）。
- **下半段**按清单展开仪器导出的检验结果——对照清单逐个检项填正常值，只对需要造边界的
  那几个时点做覆盖（少做两项、结果留空、数值超范围、多做一项方案外的）。

结果的列名跟仪器导出保持一致：检项、结果、单位、参考下限、参考上限。
**参考下限 / 上限留空是有含义的**：尿常规、HIV、乙肝是文字结果，本来就没有参考范围；
PK 采血只给了上限，那是单侧限。

## 故意造的边界值

| 边界 | 数据里长什么样 | 期望被怎么处理 |
| --- | --- | --- |
| 提前到访 | 00102 的 SC，计划 08-21，实际 08-19 | 偏离 -2，判超窗 |
| 晚到 | 00102 的 V2，计划 09-18，实际 09-24 | 偏离 +3，判超窗 |
| 窗口已过、一条记录都没有 | 00103 的 V2 | 判「未到访」 |
| 窗口还没到 | 00101 的 V3 / V4、00301 的 EOS | 判「未到期」，不能算未到访 |
| 漏做检查 | 00103 的 V1，少做尿常规、凝血四项 | 报告里各占一行，判定「未做」 |
| 结果没出 | 00201 的 SC，尿常规结果为空 | 判「未出结果」，不是正常 |
| 同项复测 | 00201 的 V1，PK 采血出了两条 | 取先到的，标「同项多重结果」 |
| 数值超范围 | 00202 的 V2，生化全套 52（范围 0~40） | 明细判定「超出范围」 |
| 方案外多做一项 | 00202 的 V2，多做心肌酶 | 排在最后，判定「方案外项目」 |
| 编号抄丢前导零 | 结果表里一条 `2202`（本应是 00202） | 单列进「游离记录」，不并进台账 |
| 表尾合计行与说明行 | 两张表最后各一行，首列留空 | 读表时丢掉，不当成真记录 |

## 实测发现的问题与修法

1. **表尾说明行的文字，不能落在"用来判空行"的那一列。**
   第一版把「说明：本表一行一个受试者 x 访视点……」放在第三列（受试者编号），
   结果这行被当成一条真计划行读进来，`计划日期` 是空的，脚本当场拿 `None` 去减天数崩掉。
   改法：把文字挪到「中心名称」列，受试者编号留空。**换一张表，"判空"的列就变了，
   说明行放哪儿得跟着变**——不是固定在首列。
2. **到访判定不能只看"有没有晚到"。** 00102 的 SC 是提前两天到的，第一版只写了
   `实际 > 窗口止` 这一半，提前到访整个溜过去。改成一列带符号的偏离天数：
   负数是提前、正数是晚到，两头都看得见。
3. **"没到访"和"没到期"必须分开。** 计划表里的 V3 / V4 / EOS 窗口都还在后头，
   受试者当然不会来。第一版按"没有采样日期就是未到访"处理，台账里一半行报红。
   改法：给一个数据导出日，窗口终点在导出日之后的一律判「未到期」。
4. **缺项判定要按"这个访视点的清单"，不能按"全部检项"。** V2 只做四项，V1 要做五项，
   拿六项的全量清单去比，每个 V2 都会被判成缺两项。清单必须逐访视点读。
5. **报告的到访判定那一格写错了词。** 台账页签里「未到访」的行，报告抬头那格第一版
   跟着 `未到期` 的分支走了，两档混成一个词——回读校验里专门加了一条盯它。
6. **空字符串写进 Excel 读回来是 `None`。** 台账里「缺失检项」为空时写的是 `""`，
   回读断言拿 `== ""` 去比直接挂。改成写 `—`，人也更好读。

## 验证环境与已知限制

- Python 3.13，openpyxl 3.1.5；Windows / macOS / Linux 同一套代码，路径全部相对定位。
- 报告只在**实际有采样日期**的时点生成。没到访、没到期的时点只在台账里出现，不生成报告。
- 「未到期」依赖 `run.py` 里的 `DATA_CUTOFF` 常量（示例里是数据导出日 2026-09-30）。
  接自己的数据时把它改成你的导出日期。
- 参考范围只做**区间判定**，不涉及单位换算、不做性别/年龄段的分层参考区间。
  真做临床报告时这部分要按你实验室的规则补。
- 同一个检项出了两条时保留先到的、另一条只记进结论，**脚本不替你决定该用哪条**。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 台账里一堆「未到期」 | `DATA_CUTOFF` 比你的数据晚 | 改成实际的数据导出日 |
| 报告里检项全是「未做」 | 检项清单里的名字跟结果表对不上 | 对齐两边的检项名，注意空格与全角半角 |
| 台账行数比预期少 | 计划表里那一行的受试者编号是空的 | 表尾说明行别把文字放在编号列 |
| 报告里出现「方案外项目」 | 结果表里有清单上没有的检项 | 要么补进清单，要么确认是不是多做了一项 |
| 中文在别的机器上显示成方框 | 那台机器没有微软雅黑 | 改 `LABEL_FONT` / 正文里的字体名 |
| 提示缺 openpyxl | 环境里没装 | 按上面的手动装依赖命令来 |

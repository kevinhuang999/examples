# 示例：一份检验数据，按各中心自己的模板出报告

同一批检验结果，要按 **A / B / C 三个中心各自的 xlsx 模板**出报告。三个模板不是同一个文件换个名字——字段起始行不同、标签写法不同（有的夹英文括号、有的夹全角空格）、字段集合不同（B 没有「访视点」、C 多要一个「报告编号」）、明细表头位置不同、单位制也不同（B 用 mg/dL，A/C 用 mmol/L）。

脚本按**字段标签**去找值该填哪个格子，不写死坐标；输出的报告除了填进去的值，模板上的格式一格没动。

**你要碰的只有三处**：`01_raw_data/` 两张 CSV、`source/templates/` 里的模板、以及 `run.py` 顶部的字段别名与换算系数。

## 怎么跑

```bash
python run.py              # Windows 也可以直接双击
python run.py --no-pause   # 不暂停（CI / 脚本里用）
```

缺 `openpyxl` 会自动用清华源装。手动装：

```bash
python -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple openpyxl
```

想重造模板与数据（把目录恢复成刚下载的样子）：

```bash
python source/build_fixtures.py
```

## 三个模板差在哪（这就是本文要解决的问题）

| 差异点 | 中心 A（华东中心） | 中心 B（North Site） | 中心 C（华南中心） |
| --- | --- | --- | --- |
| 字段起始行 | 第 3 行 | 第 2 行 | 第 2 行 |
| 标签写法 | `样本编号：` | `样本编号 (Sample ID)：` | `样本编号　：`（夹全角空格） |
| 字段集合 | 5 个 | 4 个，**没有「访视点」**，多「中心名称」 | 6 个，**多「报告编号」** |
| 明细表头行 | 第 9 行 | 第 7 行 | 第 9 行 |
| 明细预留行数 | 12 行 | 12 行 | 12 行 |
| 单位制 | 国际单位 | **常规单位**（mg/dL） | 国际单位 |
| 缺项写法 | 留空 | `未做` | `—` |

所以脚本里不许出现 `ws["B3"] = ...` 这种写法：三个中心的行号都不一样，模板上面谁插一行就整体错位，而且错的是"值填进隔壁标签的格子"这种**看着像对的错**。

## 数据故意造了哪些边界

| 边界 | 造在哪 | 脚本该怎么样 |
| --- | --- | --- |
| 样本编号前导零 | `0091` `0093` `0094` | 原样写字符串，不许变成 91 |
| 检项数超过模板明细行 | `0092` 共 13 项，模板 A 只有 12 行 | **挂起**，不出半截报告 |
| 检项极少 | `0094` 只有 1 项 | 正常出报告，不报错 |
| 结果为空 | `0091` 总胆红素、`0093` 总胆红素、`B-1008` 总胆红素 | 按各中心缺项写法：留空 / `—` / `未做` |
| 单位需要换算 | `B-1007` 葡萄糖 5.1 mmol/L | 换 91.9 且**单位列一起改成 mg/dL** |
| 单位已经是对的了 | `B-1008` 葡萄糖 108 **mg/dL** | **不许再乘一次**，报"单位与换算来源不一致" |
| 没配换算系数的检项 | `B-1007` 钾 4.2 mmol/L | 原样写，不报异常（本来就不用换） |
| 配置表里没有的中心 | `0095`（中心 `D9`） | 单列到「待人工处理」，**不猜模板** |
| 模板要、数据里没有的字段 | 中心 C 的「报告编号」 | 按配置的前缀拼出来 |
| 数据有、模板不要的字段 | 中心 B 没有「访视点」 | 不硬塞，在台账里说明 |
| 表尾合计行 / 说明行 | 两张 CSV 各两行 | 判空列是「样本编号」，这两行不留样本编号，整行丢掉 |

## 造数据 / 写代码时实测发现的几个问题

1. **模板明细行的边框必须画**。脚本靠"表头下面的连续空行"认明细区，而 openpyxl 读回时**没有内容也没有样式的行根本不存在**（`ws.max_row` 只到表头行）→ 模板里要把明细行空行的边框画好，否则脚本以为一行都填不了。这是踩过一次才发现的。
2. **`0092` 一开始只造了 12 项**，正好等于模板明细区行数，13 项的挂起分支压根没被跑到。**边界值要卡在临界点的另一侧**，等于临界值等于没测。
3. **换算了数值就必须换单位列**。只改数值不改单位，是"数字看着对、单位是错的"，比报错危险得多。
4. **数据单位已是目标单位时绝不能按系数乘**。`108 mg/dL` 再乘 18 就是 1946，这种错会一路走到报告上。
5. **日期要顺手补格式**。openpyxl 往 `number_format` 是 `General` 的格子里写 date 对象，Excel 里显示成 `46265` 这样的序列号；脚本里判断到 General 就补 `yyyy-mm-dd`。
6. **标签要先归一化再比**。中心 B 的标签带英文括号、中心 C 的带全角空格，不先压一遍（去括号注释、去冒号与空白）就找不到字段。
7. **数据里有、模板里没有的字段不要硬塞**。中心 B 的模板压根没有「访视点」，塞进去就把下一行的标签挤掉了。

## 验证环境与已知限制

- Python 3.13 + openpyxl 3.1.5，Windows 实测；脚本本身跨平台（路径全部 `Path(__file__).resolve().parent`）。
- 模板是 xlsx。若中心给的是 Word/PDF 模板，思路一样（按标签找位置），但换库（python-docx / docxtpl），不属本示例范围。
- 模板明细区行数是硬的：脚本**不动态插行**（插行会丢模板行样式）。行数不够就挂起并报出来，去模板里补行。
- 模板里若把标签和值写在同一个合并单元格里，脚本取标签自己的坐标；值要求写在标签右边一格，这是唯一的约定。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 台账里一片「模板里找不到明细表头「检项」」 | 模板表头文字不是「检项」，或明细行没画边框 | 改表头文字，或把明细空行的边框画上 |
| 大量「模板无此字段：XXX」 | 模板的标签写法没进别名表 | 在 `run.py` 的 `FIELD_ALIASES` 里补一条 |
| 所有样本都「挂起」 | 模板明细区行数不够 | 去模板里把明细空行往下多画几行 |
| 报告里日期是 46265 这种数 | 值格没设日期格式 | 脚本已自动补 `yyyy-mm-dd`；自行改过代码的话检查这段 |
| 数值全被乘了一个系数 | 该中心配成了「常规单位」 | 确认该中心模板要的单位制，配错了把 `中心模板配置.csv` 改回来 |
| 前导零丢了（0091 → 91） | 编号被当数字写了 | 脚本按字符串写；自行改过代码的话检查是不是走了 `int()` |

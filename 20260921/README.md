# 示例：纸质样本接收单批量转线上接收单

手里的存量纸质接收单，一张一张转进线上；转的同时把手写登记的数量跟设备扫码导出的明细对一遍，
对不上的单挂起不放过。跑完得到：每单一份线上接收单（Sheet 版式）+ 一份接收单台账 + 一份差异清单。

## 目录结构

```
20260921/
├── README.md                  ← 你正在看的（先看这个）
├── run.py                     ← 入口，跑主线
├── 01_raw_data/               ← 输入（01 → 02 就是操作顺序）
│   ├── 纸质接收单_人工补录.csv     ← 从纸面上抄下来的字段，一单一行
│   └── 扫码导出_样本明细.csv       ← 设备扫码导出，一管一行
├── 02_output/                 ← 跑出来的结果（不入库）
│   ├── 线上接收单/接收单_<运单号>.xlsx
│   ├── 接收单台账.csv
│   └── 差异清单.csv
└── source/
    ├── templates/接收单模板.xlsx   ← 线上单的版式，改这个就换版式
    ├── build_fixtures.py          ← 重造模板与数据（跑坏了重来一遍）
    ├── requirements.txt
    └── run_log.txt                ← 脚本自动写（不入库）
```

你要碰的通常只有三个：`01_raw_data/` 里那两份 CSV、`source/templates/接收单模板.xlsx`、
以及 `run.py` 顶部的配置区。

## 怎么跑

```bash
python run.py              # 跑完停住等回车，方便看结果
python run.py --no-pause   # 跑完直接退出
```

缺 `openpyxl` 会自己装（走清华源）。手动装：

```bash
pip install -r source/requirements.txt
```

跑坏了想从头来：`python source/build_fixtures.py`，模板和两份 CSV 会按初始状态重建。

## 数据里故意造的边界

正常数据跑通不代表对，所以下面这些是特意埋的：

| 边界 | 埋在哪 | 期望结果 |
| --- | --- | --- |
| 运单号带前导零 | `0000712` 这类 7 位号 | 全程不能变成 `712` |
| 纸质数量抄错 | `0000713` 纸质写 2 箱、明细只有 1 箱 | 差异清单出「箱数不符」，单子照出 |
| 纸质数量抄多 | `0000714` 纸质写 10 管、明细 9 管 | 差异清单出「管数不符」 |
| 同一单多个问题 | `0000714` 还另有 2 管样本类型为空 | 一单两条问题都能报出来 |
| 条数极少 | `0000716` 整单只有 1 管 | 照常出单 |
| 条数极多 | `0000715` 整单 60 管 | 汇总数按明细算，不按纸面 |
| 温度栏空白 | `0000716` 上下限都空 | 出单，标「未记录」并进差异清单 |
| 明细里没有这一单 | `0000718` | 直接挂起，不出单 |
| 到达日期空 | `0000719` | 挂起（编不出线上单号） |
| 接收人空 | `0000720` | 挂起（没人确认） |
| 两张源表都有表尾行 | 都是第一列留空、文字放别列 | 不能被当成真单子/真样本 |

期望结果：出单 5 份、挂起 3 张、差异清单 7 条、回读校验 37 项全绿。

## 写的时候实测发现的坑

1. **纸质单上的字段不能一锅端地往线上搬。** 先分清哪些明细里本来就有（箱数、管数、样本类型，
   脚本自己算）、哪些只有纸面上才有（到达日期、时间、温度、接收人，得人工补录一次）、
   哪些该由系统生成（线上单号、确认状态、生成时间）。分完类再写代码，逻辑一下短一半。
2. **用 `csv` 读补录表，不要顺手换成 pandas。** 运单号 `0000712` 走 pandas 会默认猜成 int，
   变成 `712`，事后 `astype(str)` 也补不回前导零。真要上 pandas，必须 `read_csv(dtype=str)`。
3. **两张表粒度不同**：纸面是一单一行，明细是一管一行。必须先用运单号把明细归堆，
   再逐单比条数——拿行数去跟张数比，第一天就会出错。
4. **表尾行会让统计虚高。** 两份 CSV 都带了表尾（说明行 / 合计行），判定跳过一律看**第一列是否为空**
   （第一列是运单号）。合计数字千万别写在第一列，也别写进样本编号列，否则会被当成一条真样本。
5. **挂起的单一份都不能出。** 宁可少几份让人去查，也不能把对不上的数据先灌进线上台账——
   一旦进了台账，后面没人会回头再核。
6. **线上单号只在"当天 + 同一中心"内编流水**，号短、能一眼看出是哪天哪一批；
   日期空着就先不给号，别拿当天日期去凑，凑出来的号会跟后面补录的撞上。
7. **模板按栏目名反查行号**，不写死 `B4`、`B5` 这种坐标。模板上加一行栏目，脚本不用改。

## 验证环境与已知限制

- 环境：Python 3.13 + openpyxl（Windows / macOS / Linux 同一条命令，Windows 双击也行）。
- 温度只**记录**，不做阈值判定，也不出合规结论——那是另一件事，别混进来。
- 明细来源是设备扫码导出，不是别的系统导出；换来源只要保证「一管一行 + 有运单号」就能接。
- 版式靠既有模板，脚本只往空格里写值；模板里加栏目前先确认栏目名没跟脚本里那批重名。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报 `模板里找不到栏目「xxx」` | 模板被改过，栏目名对不上 | 改回模板栏目名，或在 `fill_form()` 的取值表里对齐 |
| 所有单都挂起「明细缺失」 | 明细 CSV 换了编码 / 列名 | 统一存 UTF-8（带 BOM 也行），列名保持「运单号」 |
| 台账里运单号少了前导零 | 中途改用了 pandas 读 | 回到 `csv.DictReader`，或 `dtype=str` |
| 差异清单多出几条莫名其妙的 | 源表表尾行第一列被填了内容 | 表尾行第一列留空 |
| 出单份数比预期少 | 有单被判定挂起 | 打开 `差异清单.csv` 看问题类型 |

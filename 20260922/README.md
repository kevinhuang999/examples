# 示例：中心实验室 TAT 超时提醒（按样本算准已耗时长，挑出要超时的）

中心实验室一天收几百管样本，每管都有方案规定的 TAT 周转时限。手工做法是打开台账、逐行
拿截止时间去减接收时间，翻一遍挑出快超的——样本一多就挑不全，等客户来投诉才发现。

这个示例把这件事做成一键：按每条样本自己的「起算口径」和「计时方式」把已耗时长算准，
扣掉该停表的时段，分成 已超时 / 即将超时 / 正常 / 已交付 / 待补数据 五档，
输出监控清单（三页，按结论刷色）和一段能直接粘进群里的催办文本。

## 判定规则（跑之前先看这三条）

| 项 | 本示例的做法 |
| --- | --- |
| 计时起点 | 按台账「起算口径」列选：写「采集」用采集时间，写「接收」用接收完成时间 |
| 计时口径 | 「自然日」＝连续时间；「工作日」＝只数工作日 09:00–17:00，一天 8 小时 |
| 停表 | 暂停记录里已结束的段按实际扣；结束为空按数据截止时刻截断；结束早于开始的整段丢弃 |

分档：

- **已超时** —— 已耗 ＞ 时限（**正好等于时限不算超时，算即将超时**）
- **即将超时** —— 剩余 ≤ max(4 小时, 时限 × 20%)，短时限项目靠前半句兜住
- **正常 / 按时交付 / 超时交付** —— 已出报告的样本只复盘当时超没超，不再进提醒
- **待补数据** —— 起点缺失、时限缺失或非正数、报告时间早于起点，单列一页等人补

## 故意造进去的边界值

正常数据跑通不代表对，这些是特意造的：

| 边界 | 在哪 |
| --- | --- |
| 前导零编号（`0000123`）、补号比常规编号长（`0001723/2`） | 台账 |
| 时间列有的带秒、有的不带 | `0000126` 等 |
| 采集时间为空、时限为空、报告时间早于起点 | `0000170` / `0000171` / `0000172` |
| 暂停结束时间为空（还没结束） | `0000162` |
| 暂停结束早于开始（录反） | `0000163` |
| 同一编号两段暂停、同一编号两条记录 | `0000164` / `0000180` |
| 采集时间晚于接收完成时间 | `0000174` |
| 已出报告但当时就超了 | `0000144` |
| 卡在时限上（已耗正好等于时限） | `0000142` |
| 跨调休周六的工作日样本 | `0000130` / `0000131` |
| 表尾合计行与说明行（第一列留空） | 三个 csv 都是 |

## 写的时候实测发现的坑

1. **合计数字不能放第一列**。脚本靠「第一列是不是空」跳过表尾，合计写进第一列，
   就凭空多出一条样本。
2. **暂停结束时间为空不能当 0 点，也不能当没暂停**。`0000162` 本来在停表，
   当 0 点会算成停了十几个小时；当没暂停又会误报超时。
3. **暂停结束早于开始要整段丢弃**，不能"取绝对值"或者"按短的算"——
   宁可少扣，也别把已耗扣成负数。
4. **工作日不能写 `weekday() < 5`**。本示例里 09-17 是假日、09-19 周六却调休上班，
   所以日历单独一张表；按 8 小时 × 天数粗算也会错，脚本按半小时逐格累加。
5. **「工作日」必须先跟业务确认是"整天算"还是"只算上班时段"**。本例取后者；
   若按整天算，周五 09:30 收的样本到周一 10:00 就是 48.5 小时，一条都不会是正常。
6. **已耗正好等于时限算不算超时，要跟客户定死**。本例「等于」不算超，
   分到即将超时（剩余 0），免得天天为一条卡线样本吵架。
7. **别用 `datetime.now()` 当截止时刻**。用常量，不然昨天的清单和今天对不上，没法复盘。
8. **`fill.fgColor.rgb` 别比字符串**。不同 openpyxl 版本前缀（`00` / `FF`）不一样，
   判 `fill.patternType == "solid"` 再比后缀才稳。
9. **读 csv 用 `csv` 模块，别顺手换 pandas**。编号走 pandas 会被猜成数字，
   `0000123` 变 `123`，`astype` 补不回来。

## 验证环境与已知限制

- Python 3.13 + openpyxl，Windows 实跑；脚本本身跨平台（路径全部相对定位）。
- 判定规则是**示例**，真实 TAT 口径要看方案与研究规格文件（如报告时限表、加急级别定义），
  上线前必须把「工作日定义、暂停范围、超时判定边界」三条跟业务确认。
- 本示例只做到"算出来 + 出清单 + 出催办文本"，不负责发出去（邮件/群机器人是另一件事）。

## 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 提示 `openpyxl 装不上` | 网络或权限 | 手动 `pip install openpyxl -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 台账读出来条数多一条 | 合计行第一列填了字 | 把合计移到第二列，第一列留空 |
| 某条样本进了「待补数据」 | 起点/时限缺，或报告时间早于起点 | 看「挂起与异常」页的说明列，补完数据重跑 |
| 一条本该正常的样本报即将超时 | 暂停记录没录 | 补暂停段（等复检、等客户回话都要录） |
| 工作日样本算出来的时长偏大 | 「工作日」被按整天算 | 确认口径，改 `WORK_START` / `WORK_END` |

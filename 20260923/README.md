# 示例：第三方检测委托单批量生成

把前台的**受理登记表**（一行一个样品）归堆成一张张**检测委托单**：能出的自动编号出单，
出不了的整单挂起、写清缺什么。运行完回读校验 22 项，打印 PASS/FAIL。

## 数据故意造了哪些边界

| 边界 | 长什么样 | 预期结果 |
| --- | --- | --- |
| 日期格式不统一 | 同一天写成 `2026-09-18`、`2026/9/18`、`2026.09.18` | 归一化后归成同一张单 |
| 客户名夹空白 | `苏州新亚电子材料有限公司　`（全角空格）、前后带半角空格 | 去空白后与干净的客户名是同一个人 |
| 同客户隔天再来 | 宏远 09-18 一次、09-19 一次 | 出两张单（日期必须在分组键里） |
| 加急只标在一行 | 启海化工两个样品，只有第 1 行标「加急」 | 整单按加急处理，备注写明是哪一行标了 |
| 客户样品编号补零 | `0000713` | 写进 Excel 仍是文本 `0000713`，不掉前导零 |
| 数量带单位 | 第 12 行填的是 `2 支` | 整单挂起，提示只填正整数 |
| 缺依据标准 | 第 11 行标准号空着 | 整单挂起，指出是哪一行缺 |
| 缺检测项目 | 第 13 行项目空着 | 整单挂起 |
| 客户名称空 | 第 14 行前台漏填 | 整单挂起 |
| 样品条数过多 | 第 15-23 行同一张单 9 个样品 | 超过单张 8 行上限，挂起并提示拆单 |
| 日期认不出 | 受理日期写 `待定` | 挂起（不兜今天），提示先确认日期 |
| 明细没占满 | 3 个样品的单只填 3 行 | 剩下 5 行保持空白，不填 0 / 不填「无」 |
| 表尾说明行 | 第一列（受理日期）留空 | 整行跳过，不当成一份委托 |

## 写的时候实测发现的坑

1. **分组键必须同时含日期和客户名**：少了日期，同一客户隔天再来一次会被并成一张单，
   样品数与项目数全错；少了客户名，同一天不同客户又会并到一起。日期与客户名都要先归一化再当键。
2. **客户名称尾巴上的全角空格（U+3000）**：不去干净就分成两张单，而且肉眼看不出差别。
   `str.strip()` 默认不处理全角空格，要显式 replace。
3. **受理日期认不出时不能兜"今天"**：兜了就是把日期没定的委托单出成当天的单，跟客户对账说不清。
   登记表里 `待定` 这种值必须整单挂起。
4. **数量别用正则抠数字**：客户原件上写的是 `2 支`，抠出 `2` 脚本能跑，
   但对单时两边说的不是一回事。整单挂起、让前台去确认单位，比默默改口径安全。
5. **挂起的单不占号**：先编号后判定的写法会给挂起单也发号，台账上多出一排空号，
   业务员回头还得解释"这几张单去哪了"。编号只发给真能出的单。
6. **模板明细空行必须画边框**：没内容又没样式的行在 openpyxl 眼里根本不存在，
   `ws.max_row` 只到表头那一行，按 `max_row` 反推明细区的写法会一行都找不到。
   本示例的 `detail_span()` 因此显式校验明细区行数，模板被改坏会直接报出来。
7. **单头字段按标签反查，不写死坐标**：模板是质量部备案的，栏目顺序改一次版坐标就全漂；
   `label_rows()` 扫一遍标签拿位置，换版不用改代码。
8. **客户样品编号要设文本格式**：不设 `number_format = "@"`，`0000713` 到 Excel 里会变成 713。
9. **受理日期写进 Excel 要设日期格式**：格子的 `number_format` 是 `General` 时，
   写进去的日期显示成 `46265` 这种序列号，看着像机器编号。
10. **明细没占满的行不能填 0 或「无」**：填了就变成"有一个数量为 0 的样品"，
    客户签字时一定会问。保持空白才是对的。
11. **表尾说明行靠"第一列是否为空"跳过**：所以说明文字千万别写进第一列
    （写进去就会被当成一份委托，多出一张假单）。
12. **`csv` 读、别用 pandas 读编号列**：客户样品编号带前导零，pandas 会猜成数字，
    事后 `astype(str)` 也补不回零。

## 验证环境与已知限制

- 验证环境：Windows 11 + Python 3.13，openpyxl 3.1；`csv` 用标准库。
- 模板明细区固定 8 行——超过 8 个样品的委托单需要拆单，本示例按"整单挂起 + 提示拆单"处理，
  没做自动拆单（拆单要客户点头，不该脚本自己定）。
- 委托单号规则 `WT + 受理日期 + 当天流水` 是本示例的口径，实际以机构自己的编号制度为准。
- 加急按"单内任一行标了加急"判整单加急；如果贵司是"样品级加急"，把 `group_orders()` 里
  那段备注逻辑删掉，改成按行取值即可。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报 `模板里找不到明细表头` | 模板被换版，明细表头里没有「样品名称」「依据标准」 | 核对模板版本，或改 `detail_span()` 里找表头的关键词 |
| 报 `模板明细区只认得 N 行` | 模板里的空明细行没画边框，openpyxl 读不到那些行 | 给明细空行补上边框，或把 `MAX_DETAIL` 改成实际行数 |
| 一张单被拆成两张 | 受理日期写法没归一化，或客户名里夹了空格/全角空格 | 看 `待补资料`/台账里两张单的客户名是不是同一个（含隐藏空白） |
| 出的单里客户样品编号变成 713 | 写入时没设文本格式 | 确认 `fill_order()` 里对编号列设了 `number_format = "@"` |
| 受理日期显示成 46265 | 格子的数字格式是 `General` | 确认写日期时设了 `number_format = "yyyy-mm-dd"` |
| 明细行数对了但内容错位 | 模板明细列顺序被改过 | 模板的明细列顺序要与 `fill_order()` 里的列号一致（1 序号 … 7 备注） |

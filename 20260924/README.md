# 示例：第三方检测报价单批量汇总与历史价比对

客户一次询价几十项，报价员照着价目表一项项查单价、按客户汇总成报价单，还要跟这家客户上次的成交价比一遍。
这个示例把这条线一次跑完：**询价明细 → 查价目表 → 按客户归堆算价 → 出报价单 → 出一张全量比对台账**。

难的不是算乘法，是**一条询价行该用价目表里的哪一行**：客户写的项目名跟价目表不一样、
同一个项目几种方法几个价、价目表里还压着没生效的调价和早就失效的旧价。

## 怎么跑

```bash
python run.py              # 跑完停住等回车（Windows 双击 run.py 也一样）

```

依赖只有 `openpyxl` 一个。脚本会先试着自己装（走清华源），装不上会提示你手动执行：

## 数据故意造了哪些边界

正常数据跑通不代表对，所以这包数据是照着"会出事的那些行"造的：

| 位置 | 造的边界 | 想验证什么 |
| --- | --- | --- |
| 价目表 | 铅含量 3 行：ICP-OES 220、XRF 130、还有一条 **2026-10-01 才生效**的 260 | 取"最后一条"会把没生效的调价提前报出去 |
| 价目表 | pH值 2 行，其中 50 元那条 **2025-12-31 已失效** | 取"第一条"会把去年的旧价报出去 |
| 询价明细 | 客户写「铅（Pb）含量测定」 | 括号注解要能压掉，锚到项目「铅」上 |
| 询价明细 | 客户写「重金属铅」 | 价目表里叫「铅含量」，靠别名表才落得上 |
| 询价明细 | 同一条询价 **没写检测方法**，而该项目有两种方法两个价 | 不能默认取第一条，要挂起让客户确认 |
| 询价明细 | 数量写成「2 件」 | 不抠那个 2，挂起回原样 |
| 询价明细 | 客户名称整个空着（2 行） | 整组挂起，且不许被"按客户名判空"的写法静默丢掉 |
| 询价明细 | 客户名尾巴粘了一个全角空格 | 不归一化就会拆成两家，出两份报价单 |
| 询价明细 | 同一编号同一项目重复两行 | 留先出现的，后一行挂起报出来 |
| 询价明细 | 客户C 恰好 10 项、客户A 恰好 5 项、客户B 4 项 | 折扣门槛的**等于**那一侧也要测到，4 项是门槛另一侧 |
| 历史成交价 | 一条记着「待定」 | 不能当 0 去算涨幅（那是除零） |
| 历史成交价 | 铅含量 ICP-OES 涨 **正好 10.0%** | 阈值取"超过"还是"达到"，卡线那一侧要跑一次 |
| 历史成交价 | 同一个项目在**两种方法**下都有成交 | 比价不按方法分开，会把 XRF 判成降幅超阈值 |

## 造数据/写代码时实测发现的问题（都已修）

1. **判空列选错，最该看见的行会被静默丢掉（本轮踩到的真坑）**：一开始读询价明细时按「客户名称」判空跳过，
   结果客户名空着的那 2 行整行消失——恰恰是必须挂起报出来的那两行。台账上只少两行，肉眼根本看不出来。
   **改法：判空一律挑"一定会有值"的那一列**（这里改用第一列「询价日期」），别拿"可能为空的字段"当筛子。
2. **别名的 key 没算进"认识的项目名"**：别名表建好了，但校验"这个项目名认不认识"用的集合只装了价目表的
   正式项目名，客户写「重金属铅」照样被判成匹配不上，别名等于白建。**改法：别名 key 也进同一个集合。**
3. **模板明细区的空行必须画边框**：不画，openpyxl 读回时这些行根本不存在（没内容又没样式），
   靠 `max_row` 反推明细区会一行都找不到。**合计行反过来——一定不能画边框**，画了就被当成可填的明细行。
4. **折扣档要按"能报出来的项数"定，不是"客户问了几项"**：挂起项不算，否则折扣按 10 项算、单上只报 9 项，
   台账跟报价单永远对不上。这条口径要跟商务定死，代码里写在常量注释上。
5. **金额必须逐行 round 后再合计**：先加总再乘折扣，遇到带小数的单价会跟报价单差一分钱，
   客户对账时第一个抓的就是这个。

## 验证环境与已知限制

- 验证环境：Windows 11 + Python 3.13 + openpyxl。实跑 **32 项回读断言全绿（PASS）**，
  输出目录里 4 份报价单 + 1 份比对台账，全部由脚本从磁盘回读复核，不看内存里的中间结果。
- 已知限制：
  - 报价基准日 `QUOTE_DAY` 是**写死的常量**。用 `date.today()` 的话换个天再跑，
    同一批询价算出来的价会变，台账说不清是谁的错。要跑别的日期，改配置区那一行。
  - 折扣只做了"按项数分档"这一种规则。按客户等级、按年度签约价这些先没做，需要时加在 `tier_rate()` 里。
  - 税、加急费、复检费只在报价单的「计价说明」里写了一句，没有进计算。
  - 匹配全靠"归一化 + 别名表"，**故意不做模糊匹配**。别名表要靠业务自己维护，
    遇到新写法把它加进价目表的「别名」列，别指望脚本猜。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报价比对表里整行不见了 | 判空列选成了可能为空的字段（如客户名称） | 换成一列一定有值的（如询价日期），见「实测发现的问题」第 1 条 |
| 项目明明在价目表里却报「匹配不上」 | 客户写法不在别名表里 | 把这种写法加进价目表「别名」列（顿号分隔），重跑 |
| 报价单里客户样品编号的前导零没了 | 单元格没设文本格式 | 脚本已按 `number_format="@"` 写；自己改代码时别漏这一句 |
| 报价日期显示成 46265 这种数字 | 往 `General` 格式的格子里写了日期 | 脚本已顺手设 `yyyy-mm-dd`；模板里改过格式的话要同步 |
| 合计行也被填了数 | 合计行画了边框，被算进明细区 | 合计行别画边框，明细空行才画 |
| 提示某个客户项数超过模板明细区 | 模板明细区只有 12 行 | 加到够用，或者把这家拆成两份报价单 |
| 报价单文件夹里少了一份 | 这家客户一项都报不出来（全是待确认） | 看出的是「待确认」页，逐项补齐资料后重跑 |

## 日志里有什么

`source/run_log.txt` 每段开头记运行主机（主机名 + 本机 IP）、开始时间与 Python 版本，
结尾记完成时间、用时与 PASS/FAIL 判定——**完成行写在暂停等回车之前**，双击跑完直接关窗口也不会丢。
追加不覆盖，所以能一眼看出是同一批数据跑了几次。把整个目录打包发给别人之前，
可以删掉那三行机器信息，或者只发代码不发这个文件。

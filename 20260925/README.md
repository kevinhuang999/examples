# 示例：检测报告按客户命名规则批量改名分发

> 一句话结论：把每家客户的命名规则、收件人、报告台账读进来，按客户模板改名、按客户拆包，
> 出一份按《检验检测机构报告发放管理要求》字段排的发放登记表，外加一份客服照抄就能发的分发清单。

对应文章：`03-自媒体/发文/待发/引流_20260925_检测报告批量改名分发.md`（第三方检测 · 报告分发题材）

## 一、这个示例解决什么

第三方检测机构（SGS 那类）出报告的流程：委托单 → 送样 → 收样通知 → 检测 → 报告 → 发票关账。
报告出齐之后这一段是最磨人的：

- 每家客户对文件名都有自己的要求：有的要报告编号打头，有的要委托单号居中，还有的客户干脆
  要求「产品名 + 日期」，连编号都不许出现；
- 一家客户可能有两个收件人（客户本人 + 客户指定的甲方），一份报告就是两次发放；
- 纸质件按合同约定寄几份，电子件只发一份，登记表上「报告数量」这一栏填的就不一样；
- 发完要回头把发放登记表补齐——制度要求登记发放编号、数量、领取单位、领取人、联系电话、发放日期。

手工做法就是复制、改名、粘进客户文件夹、再对着台账填表。名字改错一个，客户收到的就是别人的报告。

## 二、目录结构

```

├── run.py                        ← 跑主线（双击也行）
├── 01_raw_data/                  ← 原始数据（你要替换的就是这里）
│   ├── 报告台账.csv               ← 报告编号 / 委托单号 / 客户 / 产品名 / 份数 / 日期 / 状态
│   ├── 客户命名规则.csv            ← 客户 → 文件名模板 + 日期写法
│   ├── 客户收件人.csv              ← 客户 → 收件人 / 电话 / 邮箱 / 发放方式
│   └── 报告原件/                   ← 报告 PDF，文件名就是报告编号
├── 02_output/                    ← 跑完才有（不入库）
│   ├── 报告分发/<客户>/            ← 按客户拆好的分发件
│   ├── 发放登记台账.xlsx           ← 页1 发放登记、页2 待处理、页3 无对应台账原件

└── source/
    ├── templates/报告发放登记表.xlsx  ← 登记表模板，脚本只往下填行
    ├── build_fixtures.py          ← 重造模板与数据
    ├── requirements.txt
    └── run_log.txt                ← 脚本自动写（不入库）
```

你要碰的只有 `01_raw_data/` 里的三份表 + 原件目录；`source/templates/` 除非要改登记表格式，不用动。

## 三、怎么跑

```bash
# 仓库根目录下
python run.py --no-pause        # 跑完直接退出
python run.py                   # 跑完停住等回车（Windows 双击等价于这句）
python source/build_fixtures.py # 数据被改乱了，重造一份
```

缺 `openpyxl` 会自动用清华源装；装了不动就手动 `pip install openpyxl`。
解释器版本不挑，3.9 以上都能跑（用了 `f"{x!r}"` 这类基础语法）。

## 四、故意造了哪些边界数据

| 数据 | 想验什么 |
| --- | --- |
| 产品名 `铝合金/塑钢型材` | 文件名里的非法字符要换掉，不换连文件都建不出来 |
| 收件人表客户名尾巴带全角空格（U+3000） | 客户名要压成比较键，否则同一家被当两家、收件人查不到 |
| 报告日期有 `2026-09-15` / `2026.09.15` / `2026/09/16` 三种写法 | 日期要认得出，但文件名按客户自己的格式写 |
| 金鼎的命名模板只用「产品名 + 日期」，不含编号 | 两份报告算出同名 → 撞名两份都挂起 |
| 新洲这家没登记收件人 | 报告能出、没人可发 → 整家挂起 |
| 待审核报告、已作废报告 | 不能进分发件（作废件外流是合规事故） |
| 台账里有、原件目录里没有的报告 | 挂起「原件缺失」，不是悄悄跳过 |
| 原件目录里的 `0000122.pdf`（台账没有） | 前导零不许丢；游离原件单列一页，不丢也不发 |
| 表尾说明行 | 第一列留空才会被跳过，说明文字写进第一列就多出一份报告 |

## 五、写的时候实测发现的问题

1. **判定顺序就是业务顺序**：写成「状态 → 命名规则 → 收件人 → 原件 → 日期」。
   第一版造数据时金鼎忘了登记收件人，结果它两份报告全被挂成「未登记收件人」，
   **「命名撞名」那个分支压根没跑到**——等于没测。这也说明顺序反了会张冠李戴：
   客服拿着「原件缺失」的理由去补资料，补完发现还是没有收件人。
2. **原件编号全程按字符串**：老系统留下的编号是 `0000122`，转成整数就变 `122`，
   跟台账永远对不上，人还看不出错在哪。
3. **写进 Excel 的是 `date`，读回来是 `datetime`**：回读校验里直接和 `date` 比会假失败，
   得先 `.date()`。
4. **表尾说明行的文字不能放第一列**：脚本靠「第一列是否为空」跳过合计行/说明行，
   真把说明写进第一列，台账上就多出一份不存在的报告。
5. **分发件必须复制、不能移动**：原件是归档凭证，动它等于动可追溯性；
   分发目录每次重跑先 `rmtree`，否则上一版留下的文件会被当成这一版发出去。
6. **`fill_ledger()` 里的 `Font` 忘了导入**：只在函数里 `import openpyxl` 是不够的，
   `write_sheet()` 里也要把 `from openpyxl.styles import ...` 带上——报 `NameError` 才知道。

## 六、验证环境与已知限制

- 本机：Windows + Python 3.13，`openpyxl 3.1`；跨平台可用（路径全用 `Path`）。
- 实跑结果：台账 11 行 → 分发件 4 份 → 发放登记 6 行 → 挂起 7 份 → 无对应台账原件 1 个，
  回读校验 **26/26 PASS**。
- `01_raw_data/报告原件/` 里的 PDF 是**占位文件**（几十个字节），只为占位，不是真报告；
  换成你们自己的报告 PDF 即可，脚本只用到文件名。
- 没有做邮件发送：发信账号、加密口令这些跟机构环境绑定太紧，脚本只出分发件和清单，
  发信仍由人点。

## 七、排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 整家客户的报告都挂「未登记收件人」 | 客户名在 `客户收件人.csv` 里写法不同（多空格/全角） | 客户名靠比较键匹配，但建议两边写法统一 |
| 报告挂「客户命名规则缺失」 | `客户命名规则.csv` 里没有这家 | 补一行；模板里可用占位符：`{报告编号}` `{委托单号}` `{客户}` `{产品名称}` `{报告日期}` |
| 报告挂「文件名拼不出来」 | 模板里写了不认识的占位符（如 `{产品名}`） | 按上面那五个占位符改，字段名一字之差就挂 |
| 两份报告挂「命名撞名」 | 客户的模板里没有唯一编号 | 跟客户确认改名规则，或在模板里加 `{报告编号}` |
| 分发目录里少了一份 | 原件目录里没有这个编号的 PDF | 看「待处理」页的「原件缺失」，把原件放回去再跑 |
| 登记表里日期显示成 `46265` | 日期格没设格式 | 脚本已设 `yyyy-mm-dd`；手工改表格记得补上 |

# 示例：检测机构开票申请与月度关账对账（openpyxl）

把客服交上来的**开票申请单**，跟**报告完成台账**、**已开发票台账**、**客户开票规则表**摆到一起，
逐单判「能不能开」，出三张表：可开票清单、挂起清单、关账对账。

痛点不是"不会开票"，是这几件事没人替你判：报告出了没有、抬头税号齐不齐、必须凭 PO 的客户 PO 给了没有、
申请金额跟台账算出来的一不一样、这一单是不是已经开过票（作废票要能重开）、框架合同的不含税额度还剩多少。
月底关账那天被追着问的，就是"报告已经出了但票还没开"的那笔差额。

## 怎么跑

```bash
python run.py              # 跑完停住等回车（Windows 双击 run.py 也行）
python run.py --no-pause   # 跑完直接退出
```

缺 `openpyxl` 会自动用清华源装；要手动装：

```bash
pip install -r source/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

跑完会打印逐项回读校验，最后一行是 `判定：PASS（34/34 项）`——它不是把结果写出来就算完，
而是把 `02_output/开票对账台账.xlsx` 重新读回来，逐项核对数量、判定步骤、金额、客户名归一化和对账差额。

## 数据故意造的边界

正常数据跑通不代表对，所以这些坑都在数据里：

| 边界 | 在哪 |
| --- | --- |
| 委托单号前导零 `WT2026-0000715`、发票号前导零 `00012301` | 全程按文本读，转 int 就丢零 |
| 客户名里夹全角空格（`江苏瑞和制药　股份有限公司`） | 规则表里那一行，申请单里不带空格 |
| 金额带千分位逗号 | 四张表里所有金额 |
| 税率写成 `6%` / `13%` | 客户开票规则表 |
| 申请金额填错（`5,000.00`，应为 `4,770.00`） | 申请单 `WT2026-0000729` |
| 同一委托单重复申请（已开过正常票） | 申请单 `WT2026-0000716` |
| 原票已作废、这一单要重开 | 已开发票台账 `00012305` + 申请单 `WT2026-0000721` |
| 报告还没出就申请开票 | 申请单 `WT2026-0000712` |
| 新客户没进开票规则表 | 申请单 `WT2026-0000728` |
| 抬头 / 税号空着 | 申请单 `WT2026-0000727`、`WT2026-0000730` |
| 必须凭 PO 的客户 PO 号空着 | 申请单 `WT2026-0000731` |
| 框架合同不含税额度不够 | `WT2026-0000725`（C3）、`WT2026-0000726`（C1） |
| 每张表末尾各一行说明行 | 判空列那一列为空，靠它跳过 |

预期结果：申请单 16 行 → 可开票 7 张（价税合计 96,738.00 元）→ 挂起 9 行；
关账对账 6 家客户，报告已出未开票合计 175,300.00 元（不含税）。

## 写的时候实测踩到的坑

1. **判空列挑错，整张表会被静默读空**：CSV 表尾那行说明行是靠「哪一列一定有值」跳过的。
   给对照表判空时不能固定用某一张表的列（比如"申请日期"在规则表里根本不存在），
   **每张表都传它自己的键列**，否则一行都读不进来，代码还不报错。
2. **判定顺序 = 业务顺序**：资料（抬头/税号/PO）、报告是否已出、金额、重复开票、合同额度，
   这个顺序反了，挂起理由就会指向错误的动作——拿着"额度不够"去找客服，
   客服补完额度回来才发现这单报告根本没出。
3. **作废票不占额度、也不挡重开**：`状态 != 正常` 的票在「已占额度」和「已开过票」两处都要跳过，
   在「关账对账」的已开金额里也要跳过。漏一处，差额就被算小，看着像开完了。
4. **合同额度按不含税累计，不是含税**：框架合同上写的是不含税额度，拿价税合计去比会提前报超。
5. **客户名差一个全角空格就是两家**：比较键统一 `norm()`（去掉所有空白含 U+3000），
   显示名另存一份干净的，别在显示上露出空格。不要用模糊匹配——检测行业的客户名本来就长得很像。
6. **前导零全程字符串**：`WT2026-0000715`、`00012301` 一旦被转成数字，
   跟开票软件里的单号就永远对不上；写单元格时把该列设成文本格式 `@`。
7. **从系统导出的金额带 ` ￥` 和千分位逗号**：`float("12,000.00")` 会直接抛异常，先洗掉再转。

## 验证环境与已知限制

- Python 3.8+，Windows / macOS / Linux 同一条命令；只依赖 `openpyxl`。
- 本机实测：Python 3.13，`openpyxl 3.1`，34 项回读校验全绿。
- 金额用 float + `round(x, 2)`，样例数据下不会出现分位误差；如果你们的金额位数多、单据量大，
  建议把 `to_money()` 换成 `decimal.Decimal` 再算。
- 脚本只做"判别 + 出清单"，**不进任何税务/开票系统**，也不替你点"开具"——
  开票软件导入用的 CSV 是给人看一眼再导入的。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 所有单子都挂起「客户没进开票规则表」 | 客户名写法与规则表不一致（空格、全角、括号） | 用 `norm()` 的同一套写法核对，或把规则表补全 |
| 挂起行数比预想的多 | 有单子的报告还在审核，没进报告完成台账 | 这是对的，报告没出就不能开票 |
| `float` 转换报错 | 金额列里除了数字还混了「合计」「-」这类文字 | 表尾说明行别写进判空列；或在 `to_money()` 里加一行跳过 |
| 台账里委托单号变成 `20260000715` | 该列没设文本格式 | 模板里把 A 列格式设成 `@`，或看 `write_ledger()` |
| 关账差额跟财务对不上 | 有作废票被算进"已开" | 检查 `build_recon()` 里的状态过滤 |

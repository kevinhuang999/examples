# 示例：多客户检测数据汇总报表自动生成

一套检测结果明细，按**每家客户自己的报表口径**各出一页汇总报表，再汇成一份工作簿；
另出一份「不合格项明细」和一个「客户一览表」。

配套文章：`引流_20260929_多客户检测数据汇总报表一家家手工筛.md`

## 目录结构

```
20260929/
├── README.md            ← 你正在看的这个
├── run.py               ← 一键脚本（你要跑的就是它）
├── 01_raw_data/         ← 原始数据（模拟仪器导出 + 两份内部台账）
│   ├── 检测结果明细.csv      一行一个检测项结果
│   ├── 客户报表口径表.csv    每家客户要什么分组维度、表头怎么写
│   └── 判定标准表.csv        每个检测项目的判定方式与限值
├── 02_output/           ← 跑完的成品（脚本自动生成，不入库）
│   ├── 客户检测数据汇总报表.xlsx
│   └── 不合格项明细.csv
└── source/              ← 其余全部收在这里
    ├── templates/客户检测数据汇总报表模板.xlsx
    ├── build_fixtures.py   重造模板与数据
    ├── requirements.txt
    └── run_log.txt         运行日志（每次追一段）
```

**你要碰的只有两处**：`01_raw_data/` 里的三张 CSV 换成自己的，`source/templates/客户检测数据汇总报表模板.xlsx` 换成你们的报表版式。`run.py` 不用改（列名不一致时改 run.py 顶上那个常量区）。

## 怎么跑

```bash
python run.py
```

Windows 上直接双击 `run.py` 也行。脚本会自己定位目录、缺 `openpyxl` 自动用清华源装、
跑完自动回读生成的报表逐项断言并打印 PASS/FAIL。不想让它结尾等回车，加 `--no-pause`：

```bash
python run.py --no-pause
```

手动装依赖：

```bash
pip install -r source/requirements.txt
```

想重造模板和数据（会覆盖 `01_raw_data/` 与 `source/templates/`）：

```bash
python source/build_fixtures.py
```

## 报表里有什么

每页（一家客户一页）：

- **指标汇总**：送检样品数 / 检测项数 / 已判定项数 / 合格项数 / 不合格项数 / 未完成项数 / 待确认项数 / 合格率
- **分组统计**：按客户口径表指定的维度分组（有的客户按检测类别，有的按委托单号），列是「组名 / 检测项数 / 合格 / 不合格 / 合格率」
- **不合格项明细**：按客户口径决定是否列（客户不要明细就只给统计数，写一句说明）

另有第一个页签「汇总」：一家客户一行，最后一行是出不了报表的客户和原因。

## 数据故意造了哪些边界

| 边界 | 在哪 | 用来验什么 |
| --- | --- | --- |
| 结果值带「<」号 | 华泰、同安的 `铅` = `<0.01` | 直接 `float()` 会崩；报告值只给边界时怎么判 |
| 结果值是文字结论 | 恒基的 `大肠菌群` = `未检出` / `检出` | 判定方式不止上下限，还有纯文字 |
| 结果值整格空 | 恒基 `0000113` 大肠菌群 | 空值不能当 0，也不能当合格 |
| 同一样品同一项目两条结果 | 华泰 `0000102` 化学需氧量（128 / 96） | 复检重出必须去重取最新，否则同一项算两遍 |
| 已作废行的报告日期更新 | 华泰 `0000103` 镉（已出报告 0.9@09-15 / 已作废 0.3@09-16） | 作废件不能参与「取最新」，否则把不合格洗成合格 |
| 报告还没出 | 华泰 `0000104` 两个项目（审核中） | 未完成不进合格率分母，但要单独计数 |
| 判定标准表漏一项 | 同安 `总硬度` | 标准缺失要挂起待确认，不许猜、不许当合格 |
| 客户名尾巴带半角/全角空格 | 同安 `0000105` 那两行 | 不归一化会把一家客户拆成三家 |
| 客户没进口径表 | 信远电子 | 出不了报表的客户不上报表面，只在一览表挂起 |
| 三张表尾都有说明行 | 三张 CSV 最后一行 | 判空列要一张表传一个，表尾行不能被当成一条记录 |
| 编号带前导零 | 样品编号 `0000101`… | 全程按文本处理，`int()` 一转就丢零 |

## 实测发现的问题与修法

1. **判空列不能写死**。第一版拿结果明细的「委托单号」去读客户口径表——那张表没有这一列，
   每一行都被判成空行，整张表读空，代码一行错都不报。改成 `read_table(path, key_col)`，
   每张表传它自己的键列。
2. **复检去重与作废件**。第一版只按「同一样品同一项目」取第一条，128 那条不合格就一直挂着。
   改成剔掉作废件再取报告日期最新的一条，并给「同一天两条并列最新」的冲突情况单独挂起。
3. **分组合格率的分母**。一开始拿「该组项数」当分母，同安那组 3 项里 1 项待确认、2 项合格，
   算出来 66.7% 是错的——应该只拿**已判定项数**当分母（2/2 = 100.0%），
   待确认的那项不进分子也不进分母。这条是回读断言抓出来的。
4. **模板明细空行必须画边框**。不画的话 openpyxl 读回来这些行根本不存在（`max_row` 只到表头），
   脚本会以为一行都填不了。`build_fixtures.py` 里那两段 `for r in range(...)` 就是干这个的。
5. **合格率算不出时给「—」不给 0%**。一条都没判出来的客户，印 0% 会被当成「全部不合格」。

## 验证环境与已知限制

- 实测环境：Windows 11 + Python 3.13 + openpyxl 3.1，回读断言 43 项全绿。
- 只依赖 `openpyxl` 和标准库；Windows / macOS / Linux 同一条命令。
- 已知限制：一份报表只按**一个**分组维度出（客户口径表里一行一个维度）。要「先按类别再按项目」两层
  分组，得改 `summarize_client()` 里的分组键，不是加一行配置能解决的。
- 判定方式目前支持 `上限` / `下限` / `区间` / `文字` 四种。出现「折算后判定」这类规则，
  得在 `judge()` 外面先做一次数据换算，不要在判定里掺换算。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报 `按「xxx」判空后一行都没读到` | CSV 列名和 run.py 常量区对不上 | 打开 CSV 看第一行表头，改 `COL_*` 常量 |
| 报 `找不到数据文件` | `01_raw_data/` 里缺文件 | 跑 `python source/build_fixtures.py` 重造，或把三张 CSV 放进去 |
| 某家客户整家没出页 | 它没进客户报表口径表 | 看「汇总」页最后一行的备注；补上口径再跑 |
| 指标区某一格是空的 | 模板里那个标签被改过字 | 模板 A6:A13 的标签文字要和 `INDICATORS` 一致（精确匹配） |
| 分组统计一行都没填上 | 模板明细空行没画边框 | 按 `build_fixtures.py` 里 `build_template()` 的做法补边框 |
| 提示 `缺少 openpyxl` 但装不上 | 本机 pip 源不通 | 手动 `pip install -r source/requirements.txt`（可加 `-i` 镜像） |

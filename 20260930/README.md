# 示例：第三方检测「检测周期进度跟踪台账」自动生成

一张委托单现在卡在哪一步、还剩几个工作日、客户来催时该答什么——从收样日按工作日倒推销出承诺交期，
按流转环节还原当前节点，再出一份进度台账和一份今天该催的清单。

配套文章：`引流_20260930_检测周期进度跟踪台账客户一催就答不上来.md`

## 目录结构

```
20260930/
├── README.md            ← 你正在看的这个
├── run.py               ← 一键脚本（你要跑的就是它）
├── 01_raw_data/         ← 原始数据（模拟仪器导出与内部台账）
│   ├── 检测委托台账.csv      一行一个检测项目；一张委托单可以有多行
│   ├── 检测项目周期表.csv    每个检测项目的承诺周期（工作日）与分包周期
│   ├── 环节节点记录.csv      哪个单的哪个环节什么时候完成的
│   └── 工作日历.csv          每天算不算工作日（含法定假日与调休上班的周六）
├── 02_output/           ← 跑完的成品（脚本自动生成，不入库）
│   ├── 检测进度台账.xlsx
│   └── 催办清单.csv
└── source/              ← 其余全部收在这里
    ├── templates/检测进度台账模板.xlsx
    ├── build_fixtures.py   重造模板与数据
    ├── requirements.txt
    └── run_log.txt         运行日志（每次追一段）
```

**你要碰的只有两处**：`01_raw_data/` 里的四张 CSV 换成自己的（或从系统导出后改列名），
`source/templates/检测进度台账模板.xlsx` 换成你们的台账版式。`run.py` 不用改
（列名不一致时改 run.py 顶上那个常量区）。

## 怎么跑

```bash
python run.py
```

Windows 上直接双击 `run.py` 也行。脚本会自己定位目录、缺 `openpyxl` 自动用清华源装、
跑完自动回读生成的台账逐项断言并打印 PASS/FAIL。不想让它结尾等回车，加 `--no-pause`：

```bash
python run.py --no-pause
```

手动装依赖：`pip install -r source/requirements.txt`

想重造模板和数据（会覆盖 `01_raw_data/` 与 `source/templates/`）：

```bash
python source/build_fixtures.py
```

## 台账里有什么

一行一张委托单：

- **承诺周期 / 承诺交期**：周期取这张单里最长的那项检测；分包件走分包周期；交期从收样日按工作日倒推
- **当前环节 / 已完成环节 / 进度**：环节按 收样登记 → 样品前处理 → 上机检测 → 数据审核 → 报告编制 →
  报告审核 → 报告发出 的顺序还原，进度 = 已完成环节数 / 7
- **已耗工作日 / 剩余工作日**：都是工作日口径，算到 `CUTOFF` 那天（脚本里是常量）
- **状态**：正常（剩余 ≥ 2）/ 临近超期（剩余 0 或 1）/ 超期（剩余为负）/ 已出报告 / 挂起，整行刷底色
- **下一环节负责岗位**：客户来催时，客服能一句话答出"卡在数据审核，找技术负责人"

另出 `催办清单.csv`：还没出报告、且已超期或就要超期的单，按剩余工作日升序——今天该催哪几单一眼看到。

## 数据故意造了哪些边界

| 边界 | 在哪 | 用来验什么 |
| --- | --- | --- |
| 一张单两项检测、周期不同 | `WT2026-0000121` 化学需氧量(5) + pH(3) | 承诺周期要取最长的那项，取最短就会漏报临近 |
| 调休上班的周六 | 2026-09-26 | 工作日不能按 `weekday() < 5` 算，要查日历 |
| 法定假期跨月 | 10-01～10-07 | 交期倒排要能跨过一整段假期 |
| 分包件 | `WT2026-0000125` 挥发性有机物 | 周期走「分包周期」7 而不是本所周期 5 |
| 剩余正好 0 | `WT2026-0000121` | 「等于」归临近而不是正常（卡线样本最容易被漏） |
| 剩余 -1 | `WT2026-0000123` | 超期单要排在催办清单最前 |
| 检测项目没进周期表 | `WT2026-0000126` 铅含量 | 算不出交期就挂起，不许拿默认周期猜 |
| 收样日期空着 | `WT2026-0000127` | 不许拿当天日期凑，整单挂起 |
| 一条环节记录都没有 | `WT2026-0000129` | 环节缺失单独一类挂起，不报"流程跳了七步" |
| 环节时间倒挂 | `WT2026-0000131` 上机检测早于样品前处理 | 倒挂要挂起，不许按时间排序把异常洗成正常 |
| 同一环节两条记录 | 脚本会判 | 无法判断哪条为准，挂起而不是取后一条 |
| 已出报告的单 | `WT2026-0000128` | 不进催办清单，剩余工作日列留空 |
| 客户名带全角空格 | `WT2026-0000124`「华泰环境　」 | 不归一化台账上会变成两家客户 |
| 委托单号带前导零 | 全部 | 全程按字符串处理，`int()` 一转就丢零 |
| 表尾说明行 | 环节节点记录最后一行 | 判空列留空才跳过；说明文字不能放第一列 |

## 实测发现的问题与修法

1. **判断"已出报告"别拿状态词去比环节名**。第一版写的是 `if STATUS_DONE in done`，
   `done` 里是环节名（"报告发出"），状态词是"已出报告"，永远不相等——已经出的单全被算成超期，
   反而挤进了催办清单。改成 `if "报告发出" in done`。
2. **判空列不能写死**。`read_table(path, key_col)` 每张表传它自己的键列（委托台账传「委托单号」、
   周期表传「检测项目」、日历传「日期」）。写死某一列，遇到没有该列的表就把整张读空，一行错都不报。
3. **调休那次把三张单的一算全错了**。日历里把 09-26 标成"调休上班"之后，
   中间隔着 09-26 的单全部少一天，交期和剩余工作日全偏。改法是让期望值跟着日历走，
   而不是让日历迁就手算——**调休与假期一定要单独一张表**。
4. **一张单多项检测，周期取 max**。取 min 的话「样品前处理还没开始」的单会被算成"今天到期"，
   催办清单天天虚报。
5. **环节只能按流程顺序还原，不能按时间排序**。有一条单的上机检测时间被转抄成 09-28（前处理是 09-29），
   按时间排序会得出"已经到上机检测"的正常结论，把这单的转抄错误洗掉。
6. **模板明细空行必须画边框**。不画的话 openpyxl 读回来这些行根本不存在（`max_row` 只到表头）。
7. **`round()` 写进去的进度再读回来要按字符串比**。进度写成 `"57%"` 存成文本，别指望读回还是数字。

## 验证环境与已知限制

- 实测环境：Windows 11 + Python 3.13 + openpyxl 3.1，回读断言 21 项全绿。
- 只依赖 `openpyxl` 和标准库；Windows / macOS / Linux 同一条命令。
- 已知限制：一次只算一套「收样日 + 承诺周期」口径。同一张单里不同检测项目各自设交期的，
  要改成按项目行出一行（改 `build_states()` 的粒度），不是加一行配置能解决的。
- 「剩余工作日」按自然日里的工作日数算，不扣中间客户补样、复检等待的停表；
  真要停表得再加一张「暂停区间表」，在 `count_workdays()` 里跳过。
- `CUTOFF` 是脚本里的常量。改成 `datetime.now()` 会让昨天和今天跑出来的清单对不上，不建议。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 报 `按「xxx」判空后一行都没读到` | CSV 列名和 run.py 常量区对不上 | 打开 CSV 看第一行表头，改 `COL_*` 常量 |
| 报 `找不到数据文件` | `01_raw_data/` 里缺文件 | 跑 `python source/build_fixtures.py` 重造 |
| 所有单都挂起、理由全是"环节记录缺失" | 环节记录的「委托单号」和台账对不上（含空格/大小写） | 两张表的委托单号必须逐字一致 |
| 明明超期却显示"正常" | 工作日历里那几天被标成"否" | 检查 `工作日历.csv` 的节假日与调休标记 |
| 交期比自己算的早一天 | 日历里漏了一个调休上班的周六 | 补上 `是否工作日 = 是` |
| 进度百分比不是想的那样 | 进度 = 已完成环节数 / 7，按环节补齐后才算完 | 环节名称必须和 `run.py` 里的 `STEPS` 完全一致 |
| 挂起理由出现"环节不在流程里" | 环节名多了前缀（如"实验室-上机检测"） | 在 `STEPS` 里改成你们的叫法 |

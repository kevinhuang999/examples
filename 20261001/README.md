# 示例：Excel 报表模板自动填表，公式不丢（含量与判定列）

实验室一批样品做完仪器分析，结果明细在仪器软件里导出一份 CSV；要出的是一份份
**抬头写着报告编号、明细行带公式（含量、判定、合格率）的报表**。
手工把值贴进模板，最容易出的事就是：模板里的公式被贴成了死值、明细行多出来公式没跟上、
汇总的合格率还按老范围算。

这个示例用 `openpyxl` 做一件事：**值列照写，公式列一个值都不写**——
模板预置的公式按实际行数延展或清空，汇总公式的统计范围跟着实际明细行数重写，
跑完再回读一遍，确认公式还在。

## 模板长什么样

- 抬头三格：`报告编号` / `受检单位` / `检测日期`，值写在标签右边那一格。
- 第 6 行是明细表头，第 7–10 行是**预置明细行**（带边框，含量列与判定列写着公式）。
- 第 11 行是汇总行：`合格率` = `COUNTIF(判定列, "合格") ÷ (合格数 + 不合格数)`，显示成百分比。
- 第 12 行是说明行，**第一列留空**——脚本的判空列就是第一列（样品编号），
  所以说明文字必须落在第二列，落在第一列会被当成一行数据。

公式长这样（以第 7 行为例）：

```text
含量(mg/kg)  H7 = ROUND(G7*E7*F7/(D7*1000),3)
判定         J7 = IF(H7<=I7,"合格","不合格")
```

## 故意造了哪些边界

| 边界 | 数据里在哪 | 想验什么 |
| --- | --- | --- |
| 样品编号带前导零 | `QC-0001234` | 编号全程按文本走，掉零就对不上原始记录 |
| 受检单位中间夹全角空格 | 第 1 行写「上海丰味　食品有限公司」 | 不归一化会被当成两家，报表多出一份 |
| 仪器读数缺失 | `QC-0001238` | 挂起，不按 0 算 |
| 称样量缺失 | `QC-0001239` | 分母没了，挂起 |
| 稀释倍数缺失 | `QC-0001242` | 不默认按 1 算（默认 1 会把结果算小） |
| 读数写成检出限 | `QC-0001240` 的 `<0.01` | 检出限表示法不能直接参与运算，挂起 |
| 含量正好等于限值 | `QC-0001243`：0.5000 g / 读数 5.000 → 0.500 = 限值 0.5 | 判定口径 `≤` 还是 `<`，要跟客户定死 |
| 数据行多于模板预置行 | 丰味 7 行 > 预置 4 行 | 插行 + 拷样式 + 公式按行号平移 |
| 数据行少于模板预置行 | 清源 2 行 < 预置 4 行 | 多余行清值留样式，空行绝不进合格率 |
| 表尾说明行 | `仪器导出结果.csv` 最后一行 | 靠第一列判空跳过 |

## 写这份示例时实测发现的坑

1. **`data_only=True` 会把公式读成缓存值，保存后公式整列消失。** 这是最贵的一处：
   只读值的一次 `load_workbook(..., data_only=True)` 之后 `save()`，模板里的公式就没了，
   而且 Excel 打开时不报错——只是所有公式格变成死数字。**填表用 `load_workbook(path)`，别加这个参数。**
2. **公式不会跟着行数走。** 插行、拷行都不会改公式里的引用，得自己平移。
   用 `openpyxl.formula.translate.Translator`（它区分相对/绝对引用），别拿正则去替换行号。
   前提是模板里的明细行公式写成**相对引用**（`G7`、`E7`），写成 `$G$7` 平移过去也还是指第 7 行。
3. **汇总的统计范围也不跟着变。** `COUNTIF(J7:J10, ...)` 在明细变成 7 行之后还是只数 4 行，
   合格率会算错却看不出——这个错不会报错，只会静静给一个错的数。**每次都要按实际行数重写这个范围。**
4. **多余的预置行一条都不能留公式。** 空行带着 `含量` 公式时，空格子被当 0 乘，
   含量算成 0、判定算成「合格」，合格率直接被刷高。清值可以，**样式要留**（否则边框掉、印出来是白格）。
5. **`insert_rows()` 只搬格子，不搬公式引用、也不带样式**：新插的行要自己从上一行拷 `_style`。
6. **判定列的分母不要用 `COUNTA`。** 判定公式在数据不全会返回空字符串，`COUNTA` 会把它算成"有值"，
   分母虚高。用 `COUNTIF(...,"合格") + COUNTIF(...,"不合格")` 相加才是真分母。
7. **Excel 的 `ROUND` 是四舍五入，Python 的 `round()` 是银行家舍入**（`round(0.5)` = 0）。
   本批数据没踩到恰好 .5 的刻度，但**回读校验里拿 Python 算的期望值去比 Excel 公式结果时要留意这一条**。
8. **日期写进没设格式的格子，Excel 显示成 `46265`**；写日期时顺手设 `number_format = "yyyy-mm-dd"`。
9. **判空列要当参数传。** 结果明细靠「样品编号」判空、单位清单靠「受检单位」判空；
   把某一张表的判空列写死、套用到另一张表上，那张表会被整张读空——**一行错都不报**。

## 验证环境与已知限制

- Python 3.13 + `openpyxl` 3.1（本机实测 PASS，40 项回读断言全绿）。
- **`openpyxl` 不算公式。** 本示例生成的文件在 Excel / WPS / LibreOffice 里打开会自动重算；
  用 Python 再读一次缓存值会是空的（这是库的行为，不是脚本的问题）。
  所以回读校验读的是**公式字符串**，不是算出来的值。
- 模板里只有单元格样式，没有图表、图片、条件格式。**如果有这些，openpyxl 保存会丢**，
  那类模板得改用 Excel COM（本机装 Excel）或只走"值导出"路线。
- 一家单位一份报表，按 `_简称_本批日期.xlsx` 命名；单位不在清单里就不出报表（挂起）。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 生成的报表里公式全变成了数字 | 某处用了 `data_only=True` 打开又保存 | 改回 `load_workbook(path)`，模板重新生成 |
| 明细行多了，公式行没跟上 | 只插了行，没平移公式 | 用 `Translator` 按行号平移（见 `fit_detail()`） |
| 合格率比实际高 | 空行留着公式被算成「合格」，或汇总范围没改 | 清空多余行、重写汇总范围 |
| 印出来明细有空白格、没边框 | 清空时把样式一起清了 | 只清 `.value`，保留 `_style` |
| 报表数比受检单位多一份 | 单位名里夹了全角空格 | 用 `norm()` 去所有空白再归堆 |
| 样品编号少了前面的零 | 写成数字了 | 编号按文本写（`number_format = "@"`） |

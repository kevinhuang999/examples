# 示例：用口径表把导出的结果明细直接出成月度质量报表

> 一句话：报表的口径（中心叫什么、单位换算成哪个、小数点留几位、怎么分组）全部写在一张
> Excel 口径表里，脚本读口径表 + 读导出的明细，出成品报表。**口径变了改表，不改代码。**

## 你要碰的文件

```
20261004/
├── README.md                     ← 先看这个
├── run.py                        ← 一键脚本，双击或 python run.py
├── 01_raw_data/                  ← 输入（01 → 02 就是操作顺序）
│   ├── lims_export_结果明细.csv    系统导出的结果明细，35 条 + 1 行表尾说明
│   └── 报表口径.xlsx              ★ 你要维护的就是这张表（3 个工作表）
├── 02_output/                    ← 跑完的成品（脚本自动生成）
│   └── 月度质量报表_2026-09.xlsx
└── source/
    ├── templates/月度质量报表模板.xlsx   报表模板：表头 + 12 行明细区 + 合计行
    ├── run_log.txt                     运行日志（每跑一次追加一段）
    ├── build_fixtures.py               重造上面的表与数据
    └── requirements.txt
```

## 三条表怎么分工

| 工作表 | 每一行是 | 改它会怎样 |
| --- | --- | --- |
| `中心字典` | 中心代码 → 中心名称 | 报表里多/少一个中心、中心改名都靠它 |
| `项目口径` | 一个检测项目：目标单位、换算系数、小数位 | 单位换成 mg/dL、小数点从 2 位改 3 位都靠它 |
| `报表定义` | 一份报表：输出文件名 + 中心列表（竖线分隔） | 想让某个中心单独出一份报表，改这一格 |

**换算系数 = 目标单位 ÷ 来源单位。** 例：残留溶剂导出来是 mg/L，报表要 mg/dL，系数写 0.1。

## 怎么跑

```bash
python run.py              # 跑完暂停，方便双击看结果
python run.py --no-pause   # 不暂停，给自动化用
```

缺 openpyxl 会自动走清华源装。跑完会打印逐项回读断言和总判定，本次为 **26 项全 OK / PASS**。

## 数据里故意造了哪些边界

正常数据跑通不代表对，这份数据是照着会出问题的地方设计的：

- **一个中心 8 个项目，一个中心只有 2 个**：明细区预留 12 行，填不满的要「清值留边框」，
  否则上次跑遗留的值会跟着这次发出去；直接删行又会把边框删掉、打印是白格。
- **结果列有四种形态**：纯数值、`<0.01`（只给边界）、`未检出`（文字结论）、空。
- **有一条记录把单位写进了结果列**（`98.6 g/L`），单位列反而是空的。
- **状态列五种取值**：已出报告 / 已作废 / 复检中 / 空，只有「已出报告」进统计。
- **判定栏出现 `—`**：说明这项还没判，不能算合格也不能算不合格。
- **样本编号带前导零**（`0000081`）、**有一条中心名称尾巴上带全角空格**。
- **每张表尾部都有说明行**，判空列留空才会被跳过。

## 实测发现的问题与修法

1. **判空列不能写死。** 一张表用「检测项目」判空、另一张表根本没有这一列，硬套会把整张表读成空，
   而且一行错都不报。`read_rows(path, sheet, key_col)` 把判空列做成参数，每张表传自己的键列。
2. **`<0.01` 不能按 0.01 算。** 它只是「小于线性下限」，按 0.01 计入均值会把整列均值拉低；
   `未检出` 按 0 算更离谱。所以结果先分形态（`num` / `limit` / `text` / `empty`），**只有 `num` 进均值**。
3. **合格率的分母不是「项数」。** `—` 和空判定代表还没判，必须单独记「未判定」，
   分母只算「合格 + 不合格」。示例里上海中心的炽灼残渣只有 1 条且未判定，合格率是空值而不是 0%。
4. **中心名称里的全角空格会带进工作表名。** `"广州中心　"` 直接当工作表名，看起来一样、实际不是同一个名字。
   比较前一律过 `norm()`（去所有空白，含 U+3000）。
5. **模板里预留的明细行要留边框。** 脚本按标签反查表头行与合计行，中间那段就是明细区；
   填不满的行只把值清掉，边框一格不动。
6. **单位换算与小数位是报表口径，不是数据自带的。** 数据里是 mg/L，报表要 mg/dL，
   这件事只能写在口径表里；写进代码就等于每换一个客户改一次代码。

## 已知限制

- 明细区预留 12 行：一个中心的检测项目超过 12 个，需要先把模板的明细区加长（加行时记得给新行画边框）。
- 明细文件是「一条记录一行」的长表。如果导出的是「一个样品一行、检项横排」的宽表，
  需要先转成长表再喂进来。
- 口径表里的换算系数是固定值。要按温度、浓度分段换算的话，得再加一张系数表。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 读入明细 0 条 | CSV 第一列不是样本编号，或文件编码不是 UTF-8/GBK | 看 `01_raw_data/` 里的文件名与表头，用 `记事本` 另存为 UTF-8 带 BOM |
| 报「中心代码 XX 在中心字典里找不到」 | 明细里的中心代码没进 `中心字典` | 把缺的中心代码补进 `中心字典`，别在代码里加分支 |
| 某个项目没出现在报表里 | 该项目所有记录的状态都不是「已出报告」 | 看「未纳入清单」页，原因写在最后一列 |
| 均值那一列是空的 | 该项目全是 `<`、`>`、文字结论或空值，没有纯数值 | 正常，不是 bug；需要均值就把口径改到能出数值的写法 |
| 工作表名看着一样却不是同一个 | 名称里有全角空格或看不见的字符 | 在 `中心字典` 里重敲一遍，别从别处复制粘贴 |
| 打印出来明细区是白格 | 模板明细行的边框被删了 | 重新跑 `python source/build_fixtures.py` 生成模板 |

# 示例：把各仪器导出的结果文件批量解析成一张汇总表

一个文件夹里躺着三台仪器导出的结果文件，格式各不一样：HPLC 的 txt 是 GBK、制表符分隔、前面压两行仪器信息；
GC 的 csv 第一行是标题、第二行才是表头；紫外的 xlsx 表头在第一行、列名是英文。另外还有两份「问题文件」。
脚本按一张格式表把它们读进来，归一成一张汇总表，并把读不了的、重复的、互相打架的都写进挂起清单。

## 目录结构

```
20261005/
├── README.md                      说明与排错（先看这个）
├── run.py                         一键脚本（跑的就是它）
├── 01_raw_data/                   原始数据：三台仪器的导出文件 + 两份问题文件
│   ├── HPLC工作站_结果_20261005.txt
│   ├── GC工作站_结果_20261005.csv
│   ├── 紫外分光光度计_结果_20261005.xlsx
│   ├── 紫外分光光度计_结果_20261005 (1).xlsx    同一批数据导了两遍
│   ├── 天平导出_原始记录_20261005.txt           认不出的文件
│   └── 酶标仪_结果_20261005.csv                 只有表头、没有数据
├── 02_output/                     跑完的成品（脚本自动生成，不入库）
│   └── 仪器数据汇总_20261005.xlsx
└── source/
    ├── run_log.txt                运行日志（每次追加，不入库）
    ├── build_fixtures.py          重新生成 01_raw_data 里的 6 个文件
    └── requirements.txt
```

你要碰的只有两个：把新文件丢进 `01_raw_data/`，在 `run.py` 顶部的 `FORMATS` 里加一行。

## 怎么跑

```bash
python run.py              # 跑完暂停，方便双击看结果
python run.py --no-pause   # 不暂停
```

Windows 上直接双击 `run.py` 也行。依赖只有 openpyxl，缺了脚本会自己走清华源安装；
想手动装：`pip install -r source/requirements.txt`。

## 输出

`02_output/仪器数据汇总_20261005.xlsx`，四个工作表：

| 工作表 | 一行是 |
| --- | --- |
| 汇总 | 一条检验记录：仪器、源文件、样品编号、批号、项目、结果原值、数值、单位、形态、分析日期 |
| 按仪器统计 | 一台仪器：条数、可算数值、文字结论 |
| 按项目统计 | 一个「检验项目 + 单位」组合：条数、数值均值 |
| 挂起清单 | 一条没进汇总的记录或一个文件，以及为什么 |

## 数据故意造了哪些边界

| 文件 | 边界 |
| --- | --- |
| HPLC txt | GBK 编码、制表符分隔、表头在第 3 行、表尾有「合计 4 条」、样品编号 0000713 带前导零、结果有 `<0.01` |
| GC csv | 带 BOM、第 1 行是标题、批号 00903 带前导零、结果是「未检出」、表尾有说明行 |
| 紫外 xlsx | 列名英文、表头在第 1 行、日期是真正的日期值、结果 `12.3 mg/L` 自带单位而单位列空着 |
| 紫外 (1).xlsx | 一条与上表完全一致（重复导出）、一条同样品同项目结果不同（97.1 vs 98.5） |
| 天平 txt | 有内容但没有表头特征列名 → 整份认不出 |
| 酶标仪 csv | 表头齐全但一行数据都没有 → 0 条不是 0 条，是读失败 |

## 实测发现的问题与修法

1. **`parse_result()` 返回的键名必须与汇总表列名一致**：第一版返回的是「原值」，而汇总表列叫「结果原值」，
   去重判重时直接 `KeyError`。键名统一成列名，后面所有地方就不用再翻译一次。
2. **结果列不是数字**：`<0.01` 直接 `float()` 会崩；按 0.01 算会把均值拉高；「未检出」按 0 算会把均值拉低，
   且两者都不报错。所以先分形态（数值 / 限度 / 文字 / 空），**只有前两种进均值**，形态本身也写进汇总表。
3. **「未检出」不进均值、也不能当 0**：示例里甲醇那条如果按 0 参与计算，项目均值就会从「—」变成一个看着很正常的数。
4. **单位有两个来源**：单位列有值以它为准；空着才从结果里拆（`12.3 mg/L`）。只改数值不改单位，比报错更危险。
5. **批号前导零**：`00903` 必须按文本格式 `@` 写单元格，否则 Excel 显示 903。
6. **日期格要设 `yyyy-mm-dd`**：紫外那份导出的日期是真正的日期值，不设格式 Excel 显示成 46265。
7. **重复导出与结果冲突是两回事**：内容一致 → 只留先读到的那份并记一条挂起；
   内容不一致 → 先把先到的那条撤出汇总，两条一起挂起。**不许取后一条**——那等于把错误洗白。
8. **判空列按格式配置传**：三种文件靠的都是「样品编号」判空，但这件事写进格式表、不写死在函数里；
   换成按批号判空的仪器，只改格式表那一格。

## 验证环境

- Windows 11 + Python 3.13（openpyxl 3.1），`run.py --no-pause` 实跑，回读断言 27 项全 OK、判定 PASS，用时 0.5s。
- 输出：汇总 9 条、按仪器 3 台、按项目 6 组、挂起 6 条。
- 已知限制：只处理「一个表头 + 一张明细」的扁平结构；固定宽度文本、多工作表、多表头的复合文件不在本示例范围内，
  遇到会走「表头特征行找不到」挂起，不会静默读错。

## 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 某个文件进了挂起清单，原因是「表头特征行找不到」 | 这个文件不是格式表里那三种仪器导出的，或导出设置变了 | 打开文件看表头列名，要么把它归到某种格式，要么在 `FORMATS` 里加一行 |
| 表头下面没有数据行 | 只有表头的空文件，或者导出中断了 | 重新导一次；这属于异常，不要当 0 条数据处理 |
| 结果列全是「空」 | 结果列名和格式表里的列名对不上（比如多了括号、空格） | 照 `norm()` 的口径比对：它比较前会去掉所有空白 |
| 项目统计里同一个项目出现两行 | 同名项目单位不同（`%` 与 `mg/L`） | 这是故意的——混算均值没有意义，要合并就先把单位统一 |
| 数字后面带单位，均值看着不对 | 该行单位列空着，单位是从结果里拆的 | 在仪器软件里把单位列打开，比在脚本里兜底可靠 |

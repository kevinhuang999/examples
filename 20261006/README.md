# 示例：仪器导出的结果文件自动入库（SQLite 单文件库）

一批仪器导出的结果文件（CSV / TXT / 不同编码 / 表头行不齐），跑一条命令，全部按统一结构写进
`02_output/lab_results.db`。重复导入不会重复入库，复检重出会留下旧版本，同一天同一个键出两个不同结果时
两条都不当有效值用。

## 目录结构

```
20261006/
├── README.md                        ← 先看这个
├── run.py                           ← 你要跑的就是它
├── 01_raw_data/                     ← 原始数据（仪器导出的文件，只读）
│   ├── 仪器导出_20261005/           ← 第一批：4 个文件
│   └── 仪器导出_20261006/           ← 第二批：2 个文件（脚本会重放一遍，验证幂等）
├── 02_output/                       ← 生成结果
│   ├── lab_results.db               ← 入库后的库（4 张表）
│   └── 入库台账.csv                 ← 每批一行：新增/更新/冲突/挂起
└── source/
    ├── templates/字段与格式说明.md   ← 主键、结果三形态的对照表
    ├── build_fixtures.py            ← 重造 01_raw_data（上半建文件、下半写说明）
    ├── requirements.txt
    └── run_log.txt                  ← 每次运行的日志（追加）
```

你要碰的只有 `01_raw_data/`（换成自己的导出文件）和 `run.py` 顶部的配置区。

## 怎么跑

```bash
python run.py              # Windows 双击 run.py 也可以
python run.py --no-pause   # 跑完不等回车
```

本示例只用 Python 标准库（`sqlite3` / `csv`），不需要装任何包。唯一前置条件是
**SQLite >= 3.24**（`ON CONFLICT DO UPDATE` 要用），脚本启动时会打印版本号并检查。

想重造原始数据：`python source/build_fixtures.py`。

## 库里的四张表

| 表 | 一行是什么 | 关键列 |
| --- | --- | --- |
| `results` | 一个样品一个项目一个单位的**当前**结果 | 主键 = 样品编号 + 检测项目 + 单位；含版本号、首次入库时间、记录状态 |
| `result_history` | 被新版本替下来的旧结果 | 含替换时间、替换批次、原版本号 |
| `ingest_pending` | 没能入库的行（挂起） | 批次、来源文件、行号、原因 |
| `ingest_log` | 每批一行 | 文件数、读出行数、新增/更新/无变化/旧版本跳过/冲突/挂起、判定 |

## 故意造了哪些边界

| 边界 | 在哪 |
| --- | --- |
| 结果低于下限 `<0.01` / 文字结论 `未检出` / 结果格留空 | 第一批 HPLC 文件 |
| 样品编号为空（缺键） | 两批里各一行 |
| 检测日期写成 `2026/10/05`（斜杠） | 第一批天平文件 |
| 检测日期写成 `待定`（认不出） | 第二批 GC 文件 |
| GBK 编码 + 制表符分隔 | 两个 `.txt` |
| 表头不在第一行（前面是仪器信息） | UV 文件 |
| 前导零样品编号 `0000081` | 全部文件 |
| 同键：日期更晚（更新）/ 同日不同值（冲突）/ 日期更早（旧版本跳过）/ 同值（无变化） | 第二批 |
| 单位列留空 | 第二批 `0000091` |

## 实测发现的问题

1. **表尾说明行里带分隔符，会被切成一行数据。** 第一版的说明行写成
   `导出说明:结果按原始打印,未做修约`，逗号把它切成两格，第二格落进「检测项目」列，
   于是这行被当成一条数据、挂进 `ingest_pending`，多出一条假挂起。改成全角逗号才干净。
2. **判空列不能选样品编号。** 缺样品编号的行本来就是要点出来的挂起作用之一，
   拿样品编号判空会把它当表尾行直接丢掉，永远进不了挂起清单。本示例判空列用「检测项目」，
   表尾说明行的这一列留空。**每换一张表先问一句：靠哪一列判空。**
3. **`INSERT OR REPLACE` 会悄悄改掉 rowid 和首次入库时间。** 更新分支一开始想图省事写
   `INSERT OR REPLACE`，实测发现它删旧行插新行，`首次入库时间` 被清成现在、`result_history`
   也白写了。改用 `ON CONFLICT(样品编号,检测项目,单位) DO UPDATE SET ...`，
   并且在 `SET` 里**不出现** `首次入库时间`。回读校验专门断言「history 与主表的首次入库时间一致」。
4. **日期字符串要先归一才能比大小。** `2026/10/05` 与 `2026-10-05` 直接比，判断"哪份更新"
   会得出错误答案。所有日期在入库前统一成 `YYYY-MM-DD`，主键里存的就是归一后的值。
5. **判定顺序反了会把冲突当更新。** 先判「新来的日期是不是更晚」再判「是不是同一天」，就会在
   同一天两个不同结果时直接覆盖掉旧值。本示例的顺序是：不存在 → 同日同值 → 同日不同值（冲突）
   → 日期更晚（更新）→ 日期更早（跳过）。

## 验证环境与已知限制

- Python 3.13 + SQLite 3.53，Windows 实跑；回读校验 28 项全绿。
- 只认「一行一条结果」的导出文件。仪器要是导出一份 PDF 或谱图，得另写解析——本示例不做。
- 表尾说明行里不能出现分隔符（见实测发现第 1 条）。
- 单位不同当作不同主键（`mg/L` 与 `g/L` 各自一行），脚本不做换算，避免悄悄改掉原始口径。
- 冲突只标记不裁决：库里那行标「冲突待确认」，新来的进挂起，等人工确认后再说。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 某个文件挂「文件格式认不出」 | 后缀不在 `FORMATS` 里，或表头前 10 行找不到必需列 | 在 `FORMATS` 加一条格式，或在配置里补必需列名 |
| 一条数据都没读到 | 判空列选错（整列都空） | 换一个"一定会有值"的列当判空列 |
| 挂起里冒出一条怪记录 | 表尾说明行被切成了数据行 | 说明行里别用半角分隔符 |
| 前导零丢了 | 建表时把样品编号写成 INTEGER | 主键列一律 TEXT，写入前 `str()` |
| 提示 SQLite 版本太旧 | 低于 3.24，没有 UPSERT | 升级 Python（自带更新的 SQLite），或改成先 UPDATE 再 INSERT |
| 日期列显示成 `46265` | 用 Excel 打开 CSV 时被认成数字 | 用文本方式打开，或在 CSV 里加前导单引号 |

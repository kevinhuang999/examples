# 示例：仪器导出的检测明细按列规则清洗、格式转换（每处改动留痕）

一批仪器导出的检测明细（CSV / TXT / 不同编码 / 表头行不齐 / 全角数字 / 结果里混着单位），
跑一条命令，输出四份文件：**清洗后数据**、**清洗记录（原值→新值→用了哪条规则）**、
**挂起清单**、**清洗台账**。改了什么一眼可查，认不出的行不猜、不改、不丢。

只用 Python 标准库，不需要装任何包。

## 目录结构

```

│   ├── GC_残留_20261006.txt         ← GBK + 制表符分隔
│   ├── UV_吸光度_20261007.csv       ← 单位列整列留空
│   ├── 天平_水分_20261007.csv       ← 表头在第四行（前面是仪器信息）
│   └── 仪器说明_20261007.txt        ← 不是数据文件，用来验证"认不出也要挂起"
```

你要碰的只有 `01_raw_data/`（换成自己的导出文件）和 `run.py` 顶部的 `FORMATS` 与 `RULES`。

## 怎么跑

```bash
python run.py              # Windows 双击 run.py 也可以
python run.py --no-pause   # 跑完不等回车
```

想重造原始数据：`python source/build_fixtures.py`。

## 清洗规则怎么加

`run.py` 顶部一张表，一列一条：

```python
{"列": "单位", "动作": ["去零宽", "去空白", "全角转半角", "别名归一"],
 "映射": {"mg/l": "mg/L", "MG/L": "mg/L", "ug/ml": "μg/mL"}}
```

六个动作：`去零宽` / `去空白` / `全角转半角` / `别名归一` / `日期归一` / （派生）结果拆两列。
新来一列就加一行，清洗逻辑一个字不用改。**同一动作在不同列可以配不同组合**——
比如编号、项目名、单位要去掉内部空白；备注、样品名这类自然语言字段就得另配一个
"只去首尾"的动作（`strip_ws` 的变体），否则 `甲醇 标准品` 与 `甲醇标准品` 会被并成一个。

## 故意造了哪些边界

| 边界 | 在哪 |
| --- | --- |
| 全角数字结果 `９８.５０`、半全角混写 `0.0２５` | HPLC / GC 文件 |
| 全角空格 `U+3000` 夹在客户名里、客户名首尾有空格 | HPLC / 天平文件 |
| 零宽空格 `U+200B` 藏在样品编号中间 | HPLC 文件第 7 行 |
| 结果里混着单位 `12.3 mg/L`，单位列写 `mg/l` | HPLC 文件第 5 行 |
| 日期三种写法：`2026/10/06`、`2026.10.6`、`2026－10－06`（全角横线） | 各文件 |
| 日期写 `待定`（认不出） | GC 文件 |
| 结果 `<0.01` / `未检出` / 空白 / `待检`（词表外） | HPLC / UV 文件 |
| 结果带千分位逗号 `"3,250"` | 天平文件 |
| 客户名称为空（必填列缺值） | 天平文件 |
| 表头不在第一行、GBK 编码、制表符分隔、BOM 有无 | 各文件 |
| 前导零编号 `0000081`、两行清洗后完全同值 | 各文件 |

## 实测发现的问题

1. **`去空白` 会动内部空格，所以它是"有痕的改动"不是顺手清理。** `12.3 mg/L` 被清成
   `12.3mg/L`，留痕里老老实实记一条。对数值、编号、单位这是想要的；对备注、样品名
   就可能把两个不同的东西并在了一起——**动作按列配，不要全局统一**。
2. **不要图省事用 `unicodedata.normalize("NFKC")` 做全角转半角。** 它顺手会把
   `µ`(U+00B5) 换成 `μ`(U+03BC)、把 `Ⅲ` 换成 `III`，单位写法被悄悄改掉，
   两批数据就合不到一起。本示例只动 U+FF01–U+FF5E 与全角空格。
3. **`strip()` 管不到全角空格与不间断空格。** `"上海　复星医药"` 与 `"上海复星医药"`
   用 `strip()` 处理完仍是两个客户——要按 `[\s\u00a0\u3000]+` 去。
4. **带逗号的结果不许猜。** `3,250` 是三千二百五十还是两条数据？分不清就挂起，
   猜错的方向只有"悄悄改掉数值"一个。
5. **受控词表外的结果文字不许当结论。** `待检`、`未测` 这类不是检测结论，
   直接塞进结果列，以后统计合格率会莫名多出一批"文字结论"。本示例只认
   `未检出` 与 `ND`，其余挂起。
6. **挂起行前面已改好的格子也一起作废。** 整行不产出，留痕也不记——半条记录
   不进任何输出，否则留痕表里会留下一批对不上明细的孤儿记录。
7. **判空列不能选"会缺值的那一列"。** 缺客户名称的行本身就是要点出来的挂起项，
   拿它判空会把它当表尾丢掉。本示例判空列用「检测项目」。

## 验证环境与已知限制

- Python 3.13，Windows 实跑；回读校验 30 项全绿，同一份输入跑两遍明细指纹一致。
- 只认"一行一条记录"的导出文件；仪器导 PDF 或谱图得另写解析，本示例不做。
- **不做单位换算**（`mg/L` 与 `g/L` 各留原样）：换算会改变数值含义，得甲方书面确认口径。
- **不做缺失值填补、不做业务去重**：填补等于造数据；"这两条该不该合并"是业务判断。
  示例里天平文件就有两行清洗后完全同值——工具照样输出两行，合不合由人定。
- 表尾说明行里不要出现半角分隔符（判空列一旦被填上，说明行会被当成数据）。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 某个文件挂「文件格式认不出」 | 后缀不在 `FORMATS` 里，或表头前 10 行找不到必需列 | 在 `FORMATS` 加一条格式，或补必需列名 |
| 一条数据都没读到 | 判空列选错（整列都空） | 换一个"数据行一定有值"的列 |
| 挂起里冒出一条怪记录 | 表尾说明行被切成了数据行 | 说明行里别用半角分隔符 |
| 日期全挂起 | 日期写法不在 `parse_date` 支持的四种里 | 在函数里补一个 `strptime` 格式，不要兜今天 |
| 编号前导零丢了 | 中途用 `int()` 转过 | 编号一律当文本处理，从头到尾 `str()` |
| 某列该改的没改 | 该列不在 `RULES` 里，或动作没配 | 加一行规则，别去改清洗逻辑 |
| 客户名合并错了 | 该列配了 `去空白`（会去内部空格） | 自然语言字段换成一个只去首尾的动作 |

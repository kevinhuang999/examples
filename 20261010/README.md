# 示例：仪器导出结果文件按样品号归堆

色谱工作站（CDS）导出的结果文件命名规则不统一——有的文件名带实验室样品号，有的只有时间戳；
**样品号要靠文件里的「进样瓶位」按一张外置对照表反查**。本示例遍历导出目录，把每个结果行的
样品号认出来、按样品归堆，另外出一份**认号留痕**和一份**挂起清单**
（匹配不上 / 一份文件混多个样品 / 同一样品多条结果 / 结果非数值），
让「这批仪器数据到底对应哪些样品、哪些还对不上」一目了然，再接后面的入库。

**你要碰的只有两处**：`source/templates/样品对照表.csv`（把你们仪器的「进样瓶位 ↔ 样品号」写进去）、
`01_raw_data/`（放仪器导出的文件）。其余都不用动。

## 怎么跑

```bash
python run.py                # 跑完暂停，双击也行
python run.py --no-pause     # 不暂停（脚本 / CI）
```

缺 `pandas` / `openpyxl` 会自动从清华源装，装不上退 `--user`。
想手动装：`pip install -r source/requirements.txt`。

跑完自动回读断言，逐项打印 `OK` / `FAIL`，最后一行是总判定 `PASS` / `FAIL`。

## 认样品号的两条路（本示例的核心）

| 优先级 | 认号方式 | 什么时候用 | 认不出怎么办 |
| --- | --- | --- | --- |
| 1 | **文件名带样品号** | 老仪器命名规范，如 `RESULT_0000190_20261010.csv` | 退回第 2 条 |
| 2 | **按「进样瓶位」反查对照表** | 文件名只有时间戳，样品号在表里 | 整行挂起，原因写清瓶位 |

**两条路都走不通才挂起整份文件**（文件名认不出、且表里也没有能反查的瓶位列）。
关键代码：`sample_no_from_name()` 先扫文件名里 6 位以上的数字段，
命中对照表里的样品号才采用；没命中就交给 `classify()` 走瓶位反查。

## 数据故意造了哪些边界

| 边界 | 造在哪 | 想验证什么 |
| --- | --- | --- |
| 文件名直接带样品号 | `RESULT_0000190_20261010.csv` | 文件名认号这条路能走通 |
| 文件名只有时间戳 | `CDS_20261010090215.csv` | 必须退回按瓶位反查 |
| 一份文件混两个样品 | `CDS_SEQ_20261010_A.csv` | 按行拆开，不能整份盖一个样品号 |
| 样品号匹配不上对照表 | `CDS_20261010_unknown.csv` 的 `V99-Z9` | 整行挂起，不许"就近猜" |
| 同一样品两条结果 | `CDS_20261010_recheck.csv` 的 `V02-B2` | 打重复标记，但不擅自取数 |
| 结果非数值 | `未检出` / `ND` / `<0.05` | 原样保留，绝不当 0 |
| 瓶位列缺失 | `RESULT_0000190_20261010.csv` | 文件名认出来了就不该再要求瓶位列 |
| 同目录混入说明文件 | `仪器导出说明_20261010.txt` | 非数据后缀直接跳过 |
| 前导零样品号 | `0000182`… | 读进来不能被转成数字 182 |

实测结果：扫 6 个数据文件 → 归堆 **12 行** / 认号留痕 **6 条** / 挂起 **1 条**（V99-Z9 匹配不上），
12 项回读断言全绿。

## 造数据 / 写代码时实测发现的问题

1. **文件名已认号，就别再卡「必须有瓶位列」**：第一版把「有 `进样瓶位` 列」当成前置条件，
   结果 `RESULT_0000190_20261010.csv` 明明文件名就带了样品号，却因为老仪器的表里没有瓶位列
   被整份挂起。**认号优先级要先判文件名，再判瓶位列**——这是本轮踩到的最硬的 bug。
2. **造数据脚本要清场再重造**：`build_fixtures.py` 一开始不清 `01_raw_data/`，
   改一次文件名就多留一个"上次的"文件，重跑时归堆结果对不上、挂起莫名其妙多一条。
   现在每次重造前先清空该目录。
3. **`检测项目` 也是「组分」的同义列名**：复检文件用的是 `检测项目` 而不是 `组分`，
   第一版没把它放进别名，导致重复标记里分组键为空、看起来"没重复"。
4. **重复标记只标不取数**：同一样品同一组分多条，说明可能是复检或平行样，
   **谁对谁错是业务判断**，脚本只打标、不替人挑一条——挑错了比不挑更危险。

## 验证环境与已知限制

- Python 3.13，pandas 2.x，openpyxl 3.x；Windows 实测通过，代码无平台相关调用。
- 已知限制：文件名认号靠"6 位以上数字段命中对照表"。如果你们文件名里的数字段
  和样品号位数不一致（如样品号 `A00182` 带字母前缀），这条规则要相应放宽，
  或者干脆只走瓶位反查那条路。
- 挂起清单只记录、不自动重试：`V99-Z9` 这种要人工回仪器软件确认它到底是谁。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 某文件进了挂起清单，原因"文件名认不出…表里也没有进样瓶位列" | 两条路都不通 | 把瓶位列名补进 `pick_columns()`，或在对照表补上该样品号 |
| 原因"样品号匹配不上" | 瓶位不在对照表 | 回仪器/台账确认这个瓶位是谁，补进 `样品对照表.csv` |
| 归堆表里某样品的「检测项目」为空 | 该文件的瓶位在对照表里没填检测项目 | 在对照表第 3 列补 |
| 重复标记整列都是空 | 表里没有 `组分`/`检测项目` 这类字段 | 补列名别名，否则分组键退化 |
| 样品号列出现绿色小三角 | 该列被设成文本格式 | 正常——前导零必须按文本存，别改成数值 |
| 归堆行数比预期少 | 空行被跳过（`if not any(cells)`） | 不是丢数据；如需连空行也留，改这段判断 |

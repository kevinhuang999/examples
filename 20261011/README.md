# 示例：实验数据自动校验 + 超限报警

把一张检测结果明细表和一张规格限度表读进来，逐条判 **合格 / 超限 / 未判定**，
超限的单独出一张报警表（整行标红），未判定的另出一张并写明原因，最后给一张校验汇总。

一批几十上百条结果，人工对着限度逐条比，慢、容易漏；真超了往往是等日报汇总出来才发现。
这个示例把这一步做成一条命令。

## 目录结构

```
20261011/
├── README.md                  ← 你正在看的（先看这个）
├── run.py                     ← 跑主线：读 → 判 → 出表
├── 01_raw_data/               ← 原始数据（你要替换成自己的）
│   ├── 检测结果明细.csv        ← 仪器导出后汇总的结果明细（表头前压了三行导出信息）
│   └── 仪器导出说明_20261011.txt
├── 02_output/                 ← 脚本生成的结果（跑完才有）
│   └── 实验数据校验判定.xlsx    ← 判定明细 / 超限报警 / 未判定清单 / 校验汇总
└── source/                    ← 其余全部收在这里
    ├── templates/
    │   └── 规格限度表.csv        ← 你要碰的第二个文件：限度写这里，改限度不改代码
    ├── build_fixtures.py      ← 重造上面两张表（改坏了就跑它）
    ├── requirements.txt       ← 只有 openpyxl
    └── run_log.txt            ← 每次运行的日志（追加不覆盖）
```

**你要碰的就两样**：`01_raw_data/检测结果明细.csv`（换成自己的数据）和
`source/templates/规格限度表.csv`（换成自己的限度）。代码不用动。

## 怎么跑

```bash
python run.py               # 跑完暂停，Windows 双击也行
python run.py --no-pause    # 不暂停，脚本 / CI 里跑
```

缺 `openpyxl` 会自动从清华源装。手动装：`pip install -r source/requirements.txt`。

数据造坏或删了，重造：

```bash
python source/build_fixtures.py
```

## 输出长什么样

`02_output/实验数据校验判定.xlsx`，四个工作表：

| 工作表 | 内容 |
| --- | --- |
| 判定明细 | 26 条全量结果，报警行**整行标红**，带「适用限度 / 判定 / 方向 / 说明」 |
| 超限报警 | 只放超限的 6 条，同样标红——报警表就是给日报和 QA 直接抓走的 |
| 未判定清单 | 5 条没判出来的 + 具体原因（限度缺失 / 结果空缺 / 单位不一致 / 结果不是数值） |
| 校验汇总 | 明细条数、合格、超限、未判定、合格率 |

## 数据里故意埋的边界

正常数据跑通不代表对。这份数据专门造了这些：

| 边界 | 具体值 | 期望结论 |
| --- | --- | --- |
| 恰好等于上限 | 水分 0.5（≤0.5）、重金属 10（≤10） | 合格 |
| 略超上限 | 含量 102.3（98.0~102.0）、炽灼残渣 0.12（≤0.1） | 超限·偏高 |
| 低于下限 | 含量 97.6（98.0~102.0） | 超限·偏低 |
| 限号值 | 水分 `<0.01`（≤0.5）、有关物质 `<0.05`（≤1.0） | 合格（**不当 0、也不当超限**） |
| 文字结论 | 残留溶剂 `ND`（≤3000）、微生物限度「未检出」 | 合格 |
| 不得检出 + 检出 | 黄曲霉毒素 0.6（要求不得检出） | 超限·检出 |
| 单位写在结果里 | 重金属 `9.2 ppm`（单位列空） | 合格（单位与限度一致） |
| 单位对不上 | 含量 `98.6 g/L`（限度单位 %） | 未判定 |
| 结果为空 | 含量空、残留溶剂空 | 未判定 |
| 认不出的文字 | 有关物质「见附页」 | 未判定 |
| 项目不在限度表 | 电导率 | 未判定 |
| 项目名带全角空格 | `炽灼残渣　` | 归一后命中限度表，照常判定 |
| 限度表里有、明细里没有 | 不溶性微粒 | 不报警、不占条数 |
| 前导零样品编号 | `0000101` | Excel 里仍是文本，不吃零 |

## 造数据 / 写代码时实测发现的问题

1. **`98.6 g/L` 这种结果让正则分组数错位**——先从结果里拆单位的正则是一组，带限号值（`<0.01`）
   的是三组，第一版统一取 `group(3)`，遇到普通数值就 `IndexError`。两套正则分开写才对。
2. **项目名尾巴上的全角空格肉眼看不出来**——`炽灼残渣　`（U+3000）直接比对会判成「限度表里没有这一项」，
   于是整条数据被假挂起。所有比对前先过 `norm()`（去空白含全角、全角括号转半角、英文小写）。
3. **表头不在第一行**——仪器软件导出时上面压了三行导出信息，`header=0` 会把导出信息当成表头。
   改成「第一个非空单元格 ≥ 2 的行」才稳；也别靠行号猜，导出格式改一版行号就全错。
4. **空字符串不能当 0**——限度表里没填下限，`float("")` 崩过一次；`to_float()` 空串一律返回 `None`。
   「没有下限」和「下限是 0」是两回事。
5. **合格率的分母**——分母是「合格 + 超限」，不含未判定。含进去的话，一项还没出结果就把合格率算歪了。
6. **前导零**——`0000101` 若不设文本格式，Excel 会显示成 `101`；写完后逐列设 `number_format = "@"`。

## 验证环境与已知限制

- 实测环境：Python 3.13 / openpyxl 3.1（Windows，也可在 macOS / Linux 跑）。
- 回读断言 19 项全 OK，总判定 PASS（见 `source/run_log.txt`）。
- 已知限制：
  - 结果列认不出的写法一律判「未判定」，不做猜测性解析（宁可挂起也不猜）。
  - 「不得检出」只按「结果是文字结论 / 限号值 → 合格，数值 → 超限」判，不判断具体检出限水平。
  - 单位不一致只挂起、不自动换算（ppm ↔ % 换算要按物质分子量，不能通用）。
  - 一个项目在一个样品下出现两条结果（复检 / 平行样）时，本示例两条都判、都在明细里，不做取舍——
    谁对谁错是业务判断。

## 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `找不到规格限度表或结果明细` | 数据/模板被删了 | `python source/build_fixtures.py` 重造 |
| 大量「未判定：限度表里没有…」 | 限度表的项目名与明细对不上（错字 / 多空格） | 比对两张表的项目名，先过 `norm()` 规则手工核一遍 |
| 明明超限却判成「未判定」 | 结果单位与限度单位不一致 | 改限度表单位，或统一明细里的单位口径 |
| 表格里样品号掉前导零 | 用别的工具重新写了一遍 xlsx | 本脚本写出的 xlsx 已设文本格式；后续别再用会重算格式的方式另存 |
| 明细条数比实际少 | 表头行找错 / 中间有整行空 | 检查导出文件是否在表头前压了信息行；整行空的会被跳过 |

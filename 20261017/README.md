# 示例：稳定性考察数据自动汇总

仪器导出的稳定性考察结果（一行一个检项）→ 自动算出实际月龄、判合格、查取样超窗，最后落三张表：

- `02_output/稳定性考察汇总_长表.xlsx`：一条结果一行，带判定与标记（可筛选、可追溯）
- `02_output/稳定性考察汇总_宽表.xlsx`：一个检项一张表，一行一条考察线，一列一个时间点
- `02_output/异常清单.xlsx`：缺结果 / 方案外 / 超窗 / 不合格 / 变化超阈 / 回跳可疑

## 目录

```
20261017/
├── README.md                       ← 你先看这个
├── run.py                          ← 跑它
├── 01_raw_data/                    ← 三份输入
│   ├── 稳定性考察方案.xlsx          ← 批号 + 条件 + 起始日 + 计划时间点
│   ├── 质量标准.xlsx                ← 检项上下限
│   └── 稳定性考察结果_仪器导出.csv   ← 仪器导出，一行一个检项
├── 02_output/                      ← 跑完生成（不入库）
└── source/
    ├── templates/                  ← 本示例没用到模板，保留空目录占位
    ├── run_log.txt                 ← 每次运行的记录（不入库）
    ├── build_fixtures.py           ← 重造上面三份输入
    └── requirements.txt
```

你要碰的只有 `01_raw_data/` 里的三份输入和 `run.py` 顶部的判定口径。

## 怎么跑

```bash
python run.py              # 跑完停在窗口里，方便看结果
python run.py --no-pause   # 脚本里调用
```

Windows 上双击 `run.py` 也行。缺 `openpyxl` 会自动用清华源装。

手动装依赖：

```bash
pip install -r source/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

重造输入数据（会覆盖 `01_raw_data/`）：

```bash
python source/build_fixtures.py
```

## 判定口径在哪

`run.py` 顶部常量区，改这三行即可：

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `WINDOW_DAYS` | 15 | 取样窗口，实际取样日与计划月龄相差超过它就标「超窗」 |
| `REBOUND_LIMIT` | 0.5 | 含量比上一时间点回升超过 0.5 个百分点 → 「回跳可疑」 |
| `TREND_LIMIT` | 含量 -2.0 / 总杂 +0.3 | 相对 0 月的变化阈值 → 「变化超阈」 |

## 数据里故意造的边界

| 边界 | 造在哪 | 期望结果 |
| --- | --- | --- |
| 批号前导零（`0201`/`0202`） | 方案表存成文本，结果 CSV 里也是 `0201` | 不能变成 `201`，宽表按文本对齐 |
| 计划时间点是文本 `3月` | 结果 CSV 的「计划时间点」列 | 解析成整数 3，不做字符串比较 |
| 复测（检测次数 2） | 0202 加速 6 月含量，99.7 与 100.1 两行 | 只留末次 100.1，长表标「复测取末次」 |
| 结果为空 | 0202 长期 0 月水分 | 判「待确认」，进异常清单「缺结果」 |
| 低于定量限 `<0.05` | 0201 长期 0 月总杂 | 取 0.05 当数值判合格，标「低于定量限」 |
| 取样超窗 | 0201 长期 3 月，计划 11/05 实取 11/25 | 标「超窗」，进异常清单 |
| 超质量标准 | 0202 长期 6 月含量 94.2（限 95.0） | 判「不合格」，红字 |
| 方案外批号 | 结果里有 `0399`，方案表没有 | 判「待确认」，进异常清单「方案外」 |
| 时间点不全 | 各条考察线只测了部分时间点 | 宽表缺的点留空，不补 0 |

## 写的时候实测发现的问题

1. **批号必须按文本读**。`pandas.read_csv` 默认把纯数字批号读成 int，`0201` 变 `201`，跟方案表怎么都对不上。这里用 `csv.DictReader` 全部按字符串读，方案表写盘时把单元格设成文本格式。
2. **计划时间点不是整数**。仪器软件导出的是 `3月`、`6月` 这种带单位的文本，直接 `int()` 会崩；先 `replace("月", "")` 再转。
3. **复测不能简单 `drop_duplicates`**。同一批号同一时间点有两行，去重保留哪一行取决于文件顺序，靠不住。必须按「检测次数」取最大那条。
4. **`float("")` 会崩整批**。空结果先过 `to_number()`，返回 `None`，后面判「待确认」，不能让一个空格子把整次汇总打断。
5. **`<0.05` 直接 `float()` 会崩**，而且它其实是「低于定量限」，不是缺失值。取下限当数值参与判定，同时留标记，评审看到才知道这是上限值不是实测值。
6. **超窗要用日期算，不能用月龄差**。计划 3 月、实际 3.7 月看着只差 0.7 个月，但换成天数是差 20 天，已超 ±15 天窗口；只有按天算才不会漏。
7. **趋势判定和合格判定是两件事**。94.2 既超限又超趋势下降阈值，两条都要出现在异常清单里——只报「不合格」会让人以为只是单点超限，看不出在往下掉。

## 验证环境与限制

- 验证环境：Windows 11 + Python 3.13 + openpyxl 3.1，实跑 13 项断言全 PASS。
- 只处理「一条考察线一个条件」的结构；一个批号跨多个包装规格时，把规格并进「考察条件」列即可。
- 时间点用平均月长 `30.4375` 折算，只用于判断窗口和排序，不作为稳定性结论依据。
- 有效期回归（ICH Q1E 那种置信区间法）不在本示例范围，宽表就是给那类分析准备的数据底座。

## 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `FileNotFoundError: 01_raw_data/...` | 输入文件被移走或改名 | 跑 `python source/build_fixtures.py` 重造 |
| 宽表某列整列空白 | 该时间点这一检项没测 | 正常，缺测就留空，异常清单会提「缺结果」只有真有空值时 |
| 全部判「方案外」 | 方案表批号或条件写法与结果表不一致（多空格、全半角） | 打开两张表比对「考察条件」字符串 |
| 超窗条数比预期多 | `WINDOW_DAYS` 设得太小 | 按自家 SOP 改 `run.py` 顶部常量 |
| 中文乱码 | Excel 打开 CSV 时编码选错 | 结果 CSV 是 UTF-8 BOM，Excel 直接双击可正常识别 |

# 示例：实验室文件命名规范落地（旧文件批量改规范名）

文件夹里堆着仪器导出和历史留下的各种乱名文件，规范定了没人照做，手工一份份改不敢动。
这个示例的做法：**规则表识别旧名 → 先出预览表 → 查重挂起 → 确认后才执行，每一笔改名都写日志可回溯**。

## 目录结构

```
20261018/
├── README.md            ← 你正在看的
├── run.py               ← 入口，双击或 python run.py
├── 01_raw_data/
│   └── 待整理/          ← 乱名文件在这（build_fixtures.py 重建）
├── 02_output/           ← 跑完生成：改名预览.csv + rename_log.csv
└── source/
    ├── build_fixtures.py ← 重造待整理文件
    ├── requirements.txt
    └── run_log.txt       ← 运行日志（自动生成）
```

你要碰的只有 `run.py`；规则表、检项别名都在 `run.py` 顶部，来新命名花样就加一行。

## 怎么跑

```
python run.py            # 跑完停在窗口里
python run.py --no-pause # 跑完直接退出（脚本调用）
```

无第三方依赖，Python 3.8+ 标准库即可。

## 数据故意造了哪些边界

- 中文式日期 `2026-3-5`、`2026.3.6`、`2026年3月9日` 三种写法混着来；
- 英文命名带空格 `sample S002 CBC 20260306.csv`（检项还是英文缩写）；
- `(2)` 副本文件——它和正本会拼出同一个规范名，脚本判「冲突」挂起，留给人决定留哪份；
- 已经规范的文件（跳过不动）；
- 认不出规则的 `结果最终版改2.xlsx`（挂起，不猜）。

## 实测发现的问题

- **日期正则必须先归一再进文件名**：`2026.3.6` 直接拼进去，排序时 `2026.10.5` 会排在 `2026.3.6` 前面；
  统一成八位 `20260306` 后按名排序就是按时间排。
- **副本 `(2)` 文件是雷**：它和正本内容可能不同（比如一份是改过数据的），脚本绝不替人二选一，
  只报冲突挂起——这一步替人做主，审计上说不清。
- **规则表按顺序匹配**：一条正则一种旧命名习惯，谁先匹配上算谁的；新花样加行就行，不用改老逻辑。

## 验证环境

Windows 11 + Python 3.13，实跑 6 个文件：改名 3、已规范跳过 1、未识别挂起 1、重名冲突 1，
10 项回读断言 PASS（含改名后目录回读、日志笔数、挂起文件原地未动）。

## 排错表

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 文件被标「挂起_未识别」 | 名字不符合任何一条规则 | 看清文件内容后在 `RULES` 里加一条正则，别硬套 |
| 文件被标「冲突_新名重复」 | 另一个文件已认走这个规范名 | 两份内容多半是正本与副本，人工比对后留一份 |
| 想撤销这次改名 | — | 按 `02_output/rename_log.csv` 里的旧名↔新名逐笔改回 |
| 改名后 Excel 打开报错 | 挂起文件被手工动过 | 挂起文件脚本不碰，确认是不是手工改错了对象 |
